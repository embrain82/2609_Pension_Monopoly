생활비 위기를 실제 선택의 딜레마로 만들고, 배운 지식을 믿고 사용할 수 있게 한다.

현재 근거

비허용 사건 moving에서 생활자금 0원으로 cash 또는 deposit을 고르면 IRP 2,530,365원이 빠져나간다. “IRP 중도인출” 버튼만 막고 예금 해지·자동충당 경로는 열려 있다. 상품은 1등급을 가장 안전하게 표시한다. 퇴직급여 600만원에는 16.5%를 일괄 적용한다.

바뀔 플레이

생활자금·IRP 대기자금·IRP 보유상품을 세 영역으로 보여 준다. 계좌 안 매도는 대기자금으로만 이동한다. 계좌 밖 지급은 인출 요건 심사와 재원별 세금 계산을 반드시 거친다. 부족한 생활비는 “지출 축소 / 분할 지급 / 비상자금 사용”의 게임 선택으로 처리한다.

구현 순서와 완료 기준

구현 작업

  1. 계좌 유형(DB·DC·IRP), 자금 원천(퇴직급여·공제받은 납입·공제받지 않은 납입·운용손익), 거래 유형(매도·인출·이전)을 별도 타입으로 정의한다. 현재 본편은 IRP 모드임을 명시하고 DB·DC 비교는 안내와 향후 시나리오로 구분한다.
  2. 공통 인출 게이트를 cash/deposit/withdraw 모든 경로에 적용한다. 가상 3% 수수료는 제도 규칙에서 제거하고, 필요하면 실제 세금과 구별되는 게임 비용으로 별도 표시한다. 잔액 부족 시 사건이 무상 해결되지 않게 한다.
  3. 위험등급 표시는 실제 1~6 방향으로 정리하되, 가상 상품 등급은 “교육용 예시”로 표시한다. 게임 난이도/변동성 수치는 별도 이름을 쓴다. 위험한도 계산과 실제 주식 노출을 분리하고 적격 TDF·승인 디폴트옵션 예외를 별도 분류한다.
  4. 세제는 원천별로 계산한다. 초기 1.08억원도 원천 구성을 가진 데이터로 바꾸고, 수령 요건 예외·합산 공제한도·정책 시행일을 학습 카드와 함께 수정한다. 아래 정확성 표를 콘텐츠 명세로 사용한다.

완료 기준

  • 비허용 사건의 모든 버튼 경로에서 IRP→생활자금 유출 0원.
  • 미공제 원금·퇴직급여·공제 원금·수익만 가진 네 계좌의 수령 결과가 각각 정해진 규칙과 일치.
  • 위험등급·중도인출·수령 조건 관련 UI/퀴즈/매뉴얼의 상충 문구 0건.

모든 운용 행동을 하나의 주문·정산 규칙으로 처리한다

7–10 인일

“지금 바꿀까, 만기까지 기다릴까?”를 수치로 판단하는 거래 퍼즐이 된다.

현재 근거

리밸런싱은 전체 자산을 새 비중으로 즉시 덮어쓰고 대기주문을 비운다. 펀드 환매 주문 100만원은 이후 -10% 시장에도 100만원으로 고정된다. 12턴 펀드→TDF 교체 후 finished 상태에 13턴 매수 주문이 남는다. 이자가 아직 없는 예금 100만원 해지에서 12,000원 원금 손실이 발생한다.

바뀔 플레이

매수·매도·교체·리밸런싱은 동일한 거래 미리보기와 주문 큐를 사용한다. 돈과 상품이 어디에 있는지 “접수 → 가격 확정 → 결제” 트랙으로 보여 준다. 리밸런싱도 필요한 차액만 거래하며 비용과 대기시간을 지킨다.

구현 순서와 완료 기준

구현 작업

  1. Holding을 수량·기준가·평가액 구조로, 예금은 가입 건별 원금·약정금리·가입/만기 시점을 보관하는 구조로 바꾼다. 펀드별 가격 확정과 결제를 분리하고, 환매 수량은 가격 확정까지 가격 위험에 노출되도록 정의한다.
  2. previewTrade → validate → reserve → price → settle 공통 처리 경로를 만든다. 교체매매는 연결 주문 ID로 환매 완료 후 매수를 생성한다. 시장 노출·가용 현금·주문 예약금 중복 계산을 방지한다.
  3. 리밸런싱을 목표 비중 대비 차액 주문 묶음으로 바꾼다. 이미 접수한 주문과 충돌하면 취소 가능 여부를 안내한다. 상품 칸의 “당일 기준가 확정/해지 비용 면제” 보너스는 없애고 정보·행동 보너스로 교체한다.
  4. 12턴 종료 후 시장이 더 움직이지 않는 정산 전용 단계를 두거나 매매 종료 시점을 앞당긴다. 연결 주문이 모두 처리되거나 취소되어야 수령 계산으로 넘어간다. 예금 중도해지는 약정 이자 재계산으로 표현한다.

완료 기준

  • 모든 행동에서 전후 순자산 차이가 외부 현금흐름·손익·비용 합과 일치(원 단위 반올림 정책 포함).
  • 마지막 턴의 펀드→펀드/ETF 교체 종료 후 미해결 주문 0건.
  • 리밸런싱으로 결제 대기·해지 이자·한도를 우회할 수 없고, 추가 예금 가입이 기존 예금의 만기를 초기화하지 않음.

같은 주사위에서도 두 가지 도착지를 비교하고, 이번 판만의 지도를 완성한다.

현재 근거

24칸과 10종 효과는 이미 존재한다. 하지만 이동은 주사위 두 개의 합으로 고정되고, 보드 칸은 클릭할 수 없는 하나의 SVG 이미지다. 반복 방문의 기록이나 지역 달성 목표가 없고, 거래 메뉴는 어느 칸에서도 거의 같다.

바뀔 플레이

기본 24칸은 유지한다. 판당 2회 “경로 토큰”으로 합계 이동과 큰 주사위 한 개 이동 중 하나를 고른다. 이동 전 두 도착지 효과를 보여 준다. 지역 배지를 모으면 장식·한정된 행동 선택권을 얻으며, 상품 수익률이나 법정 한도를 보너스로 바꾸지 않는다.

구현 순서와 완료 기준

구현 작업

  1. rollResult/routeChoice/routeToken 상태를 추가한다. 주사위 난수 스트림은 유지하고 경로 선택은 기록한다. 시장은 이동거리와 무관하게 턴당 한 번만 반영한다.
  2. 4개 지역(안정·성장·생활·은퇴)에 랜드마크와 방문 도장을 둔다. “서로 다른 자산을 검토하고 이유 선택” 같은 지역 미션을 만든다. 같은 칸 반복 보상은 한 판 1회로 제한한다.
  3. 칸 정보 팝오버·도착 예정 화살표·통과 효과 미리보기를 제공한다. 보너스는 토큰/행동 선택권으로 제한하고, 특정 금융상품 매수 자체에 이해 점수를 주는 규칙을 제거한다.

fund-order		수정“그날 또는 다음 영업일” 일반화 삭제. 상품·접수 시각·투자시장에 따른 기준가 적용일과 결제일을 구분.

etf-order		유지·표현 보완이미 발생한 상승분을 새 매수자가 소급해 받지 않는다는 설명은 타당. 실제 ETF는 지정가 주문 등이 즉시 체결되지 않을 수 있음을 안내.

risk-limit		수정한도 도달 시 추가 매수가 제한된다는 답으로 변경. “한도까지만 자동 부분매수”는 게임의 주문 제안 기능이지 제도 자체가 아님.
08 · 적격 TDF
tdf-exception		개념 유지·구현 수정감독기준 충족 시 예외 가능은 타당. 현재 0.7 가중치는 실제 규제 분류와 구분하고 상품별 적격 기준을 확인.
09 · 납입·공제한도
contribution-limit		유지·조건 보완두 한도는 다르다는 정답 유지. 연금계좌 합산, 개인 납입과 퇴직급여 이전의 구분 추가.

irp-withdrawal		조건 보완단순 이사비와 무주택자의 적격 임차보증금을 구분. 해설의 “예금으로 해결”이 IRP 밖 자금인지 명확히 수정.
12 · 비상생활자금
emergency-cash		수정장기계좌 밖 완충자금이라는 핵심은 타당. 부족하면 IRP 상품 자동 매도로 지급한다는 detail과 해설 삭제.
13 · 분산
diversification		표현 보완정답은 타당. 해설의 충격이 전체를 흔들지 “못한다”를 “영향을 줄일 수 있다”로 완화.

rebalance		유지가격 변화로 달라진 비중을 목표로 복원한다는 내용 타당. 비용·결제와 목표 변경을 별도 설명.

liquidity		유지IRP 밖 생활자금과 장기계좌를 구분한다는 설명 타당. 실제 행동 규칙도 같은 방향으로 수정.
