## 설치와 실행

Node.js 22 이상을 권장합니다.

```bash
npm install
npm run dev
```

개발 서버가 출력한 로컬 주소를 브라우저에서 여세요. 서버·로그인·데이터베이스는 필요하지 않으며 앱 데이터는 브라우저 LocalStorage에만 저장됩니다.

## 품질 검증

```bash
npm run lint
npm run typecheck
npm run test
npm run simulate -- --runs=1000
npm run build
```

`simulate`는 11개 자동전략을 번갈아 실행하고, 런타임 오류, 비정상 잔액, 미종료 경기, 평균 최종자산, 목표 달성률, 별 등급 분포와 평균 최대 낙폭을 출력합니다.

## 게임 규칙의 단순화 가정

- 연금 목표용 월 환산액은 기본적으로 `최종 IRP 평가액 ÷ 240개월`의 세전 값입니다. 수령 비교의 세후 평균과 물가를 반영한 구매력 지표는 별도로 표시합니다. 일시금 선택 시 목표용 환산액에는 세후 비교 비율을 적용합니다. 수령 중 운용수익은 가정하지 않습니다.
- 12턴은 실제 12년이 아닌 압축된 의사결정 시점입니다.
- 시장 수익률은 교육용 시나리오 값이며 전망이 아닙니다.
- 펀드 주문·결제 영업일은 턴 단위로 압축합니다.
- 예금은 3턴을 교육용 만기로 간주하고, 그 전 매도 시 단순화 불이익을 적용합니다.
- 세액공제 효과는 정책 JSON의 한도와 단일 공제율로 단순 계산합니다. 개인별 실제 결과와 다를 수 있습니다.
- 중도인출 사유와 비용은 원리를 체험하기 위한 모형입니다. 실제 가능 여부는 최신 법령과 개인 상황을 확인해야 합니다.
- 리밸런싱은 직접 운용분 차액을 주문하고 매도 결제 뒤 부족한 상품을 매수합니다. 옵션 보유분은 제외하며 실제 운용비중은 가격·한도·최소금액에 따라 달라집니다.

## 정적 배포

```bash
npm run build
```

생성된 `dist/` 디렉터리를 정적 호스팅에 그대로 배포할 수 있습니다. Vite `base`가 상대경로로 설정되어 하위 경로 정적 호스팅도 지원합니다. 별도 환경변수나 서버 함수는 없습니다.

### Vercel

운영 주소: [https://2609-pension-monopoly.vercel.app/](https://2609-pension-monopoly.vercel.app/)

프로젝트 `nonsleepers-projects/2609-pension-monopoly`에 `embrain82/2609_Pension_Monopoly` 저장소가 연결되어 있습니다. Framework는 Vite, Output은 `dist`입니다. `vercel.json`이 같은 값을 고정합니다.

```bash
npx vercel login
npx vercel --yes --prod
```

`.vercel/`과 `.env.local`은 커밋하지 않습니다.

### 롤백

`main`에 푸시하면 Vercel이 프로덕션을 올립니다. 되돌릴 때는 아래 중 하나를 씁니다.

1. **커밋 되돌리기(권장).** 문제 커밋을 `git revert <sha>`로 뒤집어 `main`에 푸시합니다. 이력이 남고 Vercel이 자동으로 다시 배포합니다.
2. **태그로 돌아가기.** 배포 기준점에는 `prod-YYYY-MM-DD` 태그를 붙입니다. `git checkout prod-2026-09-04`로 그 시점을 확인하고, 필요하면 `git revert`로 그 상태까지 되돌립니다.
3. **Vercel 대시보드.** Deployments에서 이전 성공 배포를 골라 Promote to Production을 누르면 코드 변경 없이 즉시 되돌아갑니다.

기능 작업은 `codex/<이름>` 브랜치와 PR로 `main`에 넣습니다. 배포 버전은 `v1.x.x` 태그로 구분합니다.

### GitHub Pages

`.github/workflows/pages.yml`은 **수동 실행(workflow_dispatch) 전용**입니다. 저장소 Settings → Pages가 꺼져 있는 상태에서 `main` 푸시마다 실패 알림이 오는 것을 막기 위해 자동 트리거를 뺐습니다. Pages를 쓰려면 Settings → Pages → Source를 GitHub Actions로 켠 뒤 Actions 탭에서 워크플로를 직접 실행하면 됩니다.

## 2026-09-09 · P0 계좌·주문 개편

현재 구현 단계는 검토 보고서의 **① 계좌·제도 정확성 + ② 주문·정산 통합**입니다.

- IRP 안 매도와 계좌 밖 인출을 분리했습니다. 비허용 생활사건은 IRP를 자동 인출하지 않고, 부족액은 미지급 생활비로 남아 다음 급여에서 우선 지급됩니다.
- 자금 원천 원장(`account-engine.ts`): 퇴직급여·공제 원금·미공제 원금과 잔액 차이인 운용수익을 구분합니다. 납입·이전·인출 흐름은 별도로 기록합니다.
- 초기 IRP 1.08억원은 퇴직급여 9천만원(가상 영수증 이연세액 180만원), 공제 원금 900만원, 미공제 원금 900만원입니다. 퇴직급여 이전 사건의 600만원/세금 6만원도 가상 영수증 사례이며 보편적인 세율이 아닙니다.
- 연금은 55세부터 20년 균등 수령, 가입 5년 이상, 다른 연금소득·수령 중 수익 없음 가정입니다. 인출 순서와 재원·연차·나이에 따른 세금을 계산합니다. 손실 시 원금을 비례 축소하는 교육 모형으로 실제 세무 계산서가 아닙니다.
- 펀드 주문은 접수 → 다음 턴 가격 확정 → 그다음 턴 결제입니다. 매수는 가격 확정 전 수익을 얻지 않고, 환매는 가격 확정 전까지 시장 위험을 가집니다. 실제 영업일 일정은 상품별로 다릅니다.
- 교체매매는 환매 결제 후 연결 매수, 리밸런싱은 차액 주문입니다. 기존 미결 주문을 보존하고 정산까지 다른 리밸런싱을 제한합니다. 10만원 미만 차액은 거래하지 않아 소액 잔여 현금이 가능합니다.
- 마지막 턴은 가격을 고정한 정산 전용 시간으로 연결 주문까지 처리합니다. 게임 턴·시장·급여를 추가하지 않습니다.
- 예금은 가입 건별 3턴 약정·고정 금리를 보관합니다. 중도해지는 발생 이자의 50%만 지급하는 가상 약정이며 원금 차감이 없습니다. 만기 후 보관 중 추가 이자는 가정하지 않습니다.
- 위험등급은 1(매우 높은 위험) → 6(매우 낮은 위험) 방향의 가상 예시입니다. 규제상 위험자산 분류와 기초 주식 노출을 분리합니다. 적격 TDF 예외는 손실 위험이 없다는 뜻이 아닙니다.
- 12턴은 압축 체험이며 납입·공제 한도는 1년분입니다. 현재 디폴트옵션 실행은 옵트인 체험으로 표시하고, 실제 통지·대기 상태 구현은 다음 단계입니다.

새 결제 대기로 첫 분산 완성까지 시간이 필요하므로 분산 업적은 **8턴 유지**로 조정했습니다(기존 저장 ID는 보존). 나머지 점수·성향·시장 시나리오의 전면 개편은 후속 P1 단계입니다.

검증: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm run simulate -- --runs=1100`. 회계·규칙 회귀 사례는 `tests/p0-ledger.test.ts`에 있습니다.

계산 단위: 엔진은 소수 원을 유지하고 화면에서 원 단위 반올림합니다. 자금 보존 검증은 0.01원 오차 이내로 비교합니다. `feeRate`는 교육 모형의 턴당 보수율이며 실존 상품의 연 보수율이 아닙니다. 기존 다이어그램·2026-09-06 측정값은 개편 전 참고 자료입니다.

## 2026-09-12 · 납입 속도와 운용 화면 개선 (v1.6.0)

- 새 게임의 개인 추가납입은 1회 최대 200만원, 같은 턴 합계도 200만원입니다. 보너스 납입과 두 번의 운용지시가 한도를 공유하고, 미사용액은 이월하지 않습니다. 퇴직급여 이전은 제외합니다.
- 납입 화면에 이번 턴 사용액·가능액과 50만원/100만원/이번 턴 최대 버튼을 표시합니다. 미리보기와 실제 실행은 같은 계산을 사용하고, 한도 사용 후에는 제한 사유가 표시됩니다.
- 포트폴리오 확인 버튼은 모든 운용 화면의 맨 아래에 하나만 표시합니다. 왕복 시 입력·펼침·스크롤을 보존하며, 취소는 X만 유지합니다.
- 시장·보유자산 영향은 카드형 펼침 메뉴와 「상세 보기 / 접기」로 강조합니다. 같은 턴에는 펼침 상태를 유지합니다.
- 기존 저장은 이전 규칙으로 마칩니다. 챕터 복원은 그 판의 규칙을 유지하고, 같은 시드로 새로 시작하면 새 규칙을 적용합니다. 공유·복기 기록에도 규칙을 표시합니다.
- 사용자·운영자 매뉴얼과 학습 카드의 게임 가정을 갱신했습니다. 턴 한도는 실제 법정 한도와 구분하는 게임 진행용 규칙입니다.
