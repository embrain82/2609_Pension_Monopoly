## 엔진과 저장

- `contribution-engine.ts`의 순수 계산을 일반 납입·보너스·실행 가능 판정·화면에서 공유합니다. 장부 `cashFlows`의 현재 턴 납입 합계가 사용액의 기준입니다.
- 판 전체에 적용하는 기존 교육용 누적 납입 한도, 공제 한도, 생활자금과 최소 납입금액 10만원도 함께 검사합니다. 턴당 200만원은 실제 법정 한도와 구분하는 **게임 진행용 규칙**입니다.
- 매도·중도인출로 해당 턴의 납입 사용액이 복원되지 않습니다. 납입 한도를 사용해도 남은 운용 횟수로 가능한 매수·매도 등을 선택할 수 있습니다.
- 새 UI 게임에 `contributionPacing: { version: 'v1', perTurnLimit: 2000000 }`을 저장합니다. 기존 E 거래 규칙과 c3 저장 형식을 유지합니다.
- 해당 필드가 없는 C/D/E 저장은 이전 규칙으로 계속합니다. 새 규칙이 있는 저장과 각 챕터 스냅샷의 규칙·장부 일관성을 검사합니다.
- 챕터 복원은 원래 판의 규칙을 유지합니다. 같은 시드로 **새 게임**을 시작하면 새 규칙이 적용됩니다. 결과 복사와 복기 JSON에 납입 규칙을 구분해 넣습니다.
- 펼침 상태는 같은 턴의 UI 상태이며 저장 데이터에 추가하지 않습니다. 새 턴·새 판·새로고침에서는 접힙니다.
- 사용자·운영자 매뉴얼, 게임 방법, 납입 한도 학습 카드의 게임 가정을 갱신했습니다. 실제 제도 설명·퀴즈 정답·정책 검수일은 변경하지 않았습니다.

### 계획 실험 재현

`npm run verify:pacing`은 50시드 × 4시장 × 5성향 × 5후보의 **5,000판**을 재실행합니다. 200만원 후보 1,000판은 호출자가 생활자금 전액을 요청하고 **실제 엔진이 한도를 제한**합니다. 나머지 후보 4,000판은 비교용 입력 제한 방식입니다. 전체 집계와 시장별 집계가 계획 당시 원본과 정확히 일치했습니다.

| 최대 납입 우선 전략 | 이전 규칙 | 턴당 200만원 |
|---|---:|---:|
| 1턴 목표 도달 | 94.4% | 0% |
| 3턴 이내 목표 도달 | 98.8% | 7.7% |
| 최초 도달 중앙값, 도달한 판 기준 | 1턴 | 6턴 |
| 최종 목표 달성 | 88.6% | 88.6% |

이 실험은 모든 생활사건을 생활자금으로 처리하고 상품 매매·퀴즈를 생략한 고정 전략입니다. 사람의 승률이나 최적 전략을 뜻하지 않으며, 목표 도달을 특정 턴까지 보장하지 않습니다.

## 실제 브라우저

Ego Browser에서 로컬 production 빌드(`vite preview`, 별도 검증 origin)로 확인했습니다.

- 신규 동의·게임 방법·디폴트옵션 지정부터 시작해 **12턴 완주와 연금 수령 선택**까지 진행했습니다. 납입·매수·매도·교체·옵트인·리밸런싱·생활사건과 두 행동 턴을 포함했습니다.
- 복기 JSON의 버전 1.6.0, 납입 규칙, 12개 턴 기록과 3개 챕터를 확인했습니다. 9턴 챕터 복원에서도 턴 납입 200만원과 규칙이 유지됐습니다.
- 320·430px 및 1280px에서 메뉴와 여섯 하위 운용 화면 모두 가로 넘침 없이 하단에 버튼이 한 개만 표시됐습니다. 390px에서는 화면을 직접 확인하고 포트폴리오 왕복의 금액·펼침·스크롤·포커스를 확인했습니다.
- 새 규칙의 두 행동 턴 검증용 저장에서 200만원 납입 후 추가납입 비활성·사유 표시, 매수 활성, 남은 행동 1회를 확인했습니다. X 취소·재진입·새로고침으로 사용 한도가 초기화되지 않았습니다.

- 이전 규칙의 검증용 저장에서는 1,340만원 납입이 그대로 가능했고, 실행·새로고침 뒤에도 그 금액과 남은 행동이 유지됐습니다.
- 1280px 화면에 CSS 확대 200%를 적용해 납입 화면의 넘침 여부와 키보드 Enter/Space 펼침·접기, 하단 포트폴리오 왕복 및 포커스를 확인했습니다. 이 검사는 브라우저 자체 확대나 모바일 Safari 실기기 검사를 대신하지 않습니다.
