# v1.12.0 — A1 화이트 스티커 + B5 탐험 지도

## 승인과 범위

2026-09-16 사용자 선택(A1 + B5)과 “좋아 이대로 구현해보자”를 기준으로 구현했다. 원이는 검토용 선택이므로 실제 게임의 올리·원이·단지·달리·코리 선택을 유지한다.

- 캐릭터에 흰 실루엣 테두리와 작은 초록 발판을 적용하고 말을 키웠다. 이동·착지 키프레임과 두 주사위는 유지한다.
- 새 판은 출발칸만 공개한다. 경유칸은 가려두고 최종 도착칸을 공개한다.
- 마지막 착지 후 지도 스티커가 벗겨지며 이름과 고유 배경색을 함께 보여준다. 현재 위치 강조는 배경을 덮지 않는다. 공개된 칸은 떠난 뒤에도 같은 색을 유지한다.
- 재방문은 재공개하지 않는다. 동작 줄이기는 즉시 같은 결과로 전환한다.
- 지도 상세·선택 목록·중앙 문구·ARIA·이동 안내에서도 미공개 칸의 종류를 숨긴다.
- 금융상품 조회와 운용 메뉴는 그대로다. 발견 수는 도장·점수·금액과 별도로 표시한다.

## 상태와 저장

`boardVisibility?: 'open-v1' | 'arrival-v1'`은 판의 표시 규칙이다. 필드 없는 c2/c3/c4 저장은 전체 공개로 복원한다. UI에서 새로 시작한 판만 arrival-v1을 명시한다. 같은 시드 재도전은 이전 공개 방식을 유지한다.

공개된 칸은 `[0, ...route.visits]`에서 도출한다. 출발칸을 실제 방문 기록에 넣지 않으므로 도장 계산이 변하지 않는다. 장 복기는 해당 시점의 방문 기록을 사용한다. 저장 파서는 알 수 없는 공개 규칙과 장 분기에서 다른 규칙이 섞인 저장을 거부한다.

순서: 게임판으로 화면 이동 → 기존 주사위 두 개 → 기존 말 점프·착지 완료 → 신규 칸 공개(340ms, 2×에서 170ms) → 기존 `startTurn` 한 번. 공개 중에는 기존 이동 잠금을 유지해 중복 입력과 체크포인트를 막는다. 탭 중단은 임시 공개를 지우고 직전 결정 시점으로 되돌린다. 새로고침도 직전 저장에서 재개하므로 급여·시장·이자를 중복 반영하지 않는다.

## 브라우저 검증

Ego Browser의 실제 페이지에서 검증했다. 초기 진단·옵션 선택과 첫 주사위는 브라우저 입력으로 진행했고, 반복 12턴은 같은 화면의 DOM 버튼을 클릭하는 방식으로 검사했다(엔진 자동플레이 대체가 아님).

- 모바일 390×844, 데스크톱 1440×1000에서 각각 12턴 완주와 수령 확정. 완주 후 진행 체크포인트 삭제 확인.
- 모바일 1×: 최종 착지가 끝날 때까지 가림 23칸 → 공개 순간 22칸 → 턴 1회 확정. 실행 오류 0.
- 데스크톱 2×: 실제 입체 주사위 2개, 모든 경유칸 비공개, 공개 애니메이션 170ms 확인. 최종 도착의 제도 칸은 공개 순간과 정산 후 모두 rgb(244, 240, 250).
- 두 완주 과정에서 공개 칸의 색상을 추적 비교: 현재 위치일 때와 떠난 뒤 색상 변화 없음.
- 6턴에서 새로고침·이어서 플레이: 모든 게임 필드를 재귀 비교해 차이 0. 공개 수·방문 기록도 동일.
- 올리·원이·단지·달리·코리 선택 시 캐릭터 필드 외 금융 상태 변화 없음. 다섯 PNG 모두 2172×724로 디코딩 성공.
- 미공개 칸 클릭과 지도 목록에서 이름 은폐 확인.
- 기존 필드 없는 저장을 브라우저에서 복원: 24칸 전체 공개 유지.
- 320/390/768/1440 요청 뷰포트에서 보드·말 크기와 가로 레이아웃 확인. 테스트 환경의 스크롤바/모바일 확대가 실제 레이아웃 크기에 반영되므로 실기기 검증과 구분한다.

화면 캡처는 Ego의 Page.captureScreenshot 시간 초과로 확보하지 못했다. 따라서 픽셀 단위 외관 검수와 실제 iPhone Safari의 확인은 남아 있다. 이번 검증은 DOM·계산된 색상/크기·Web Animations 완료·이미지 디코딩을 직접 확인한 결과다.
