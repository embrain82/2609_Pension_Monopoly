# v1.5.1 · 플레이테스트 FB-001~003 구현·검증

2026-09-10. 기준 커밋 `3ea36a9`(v1.5.0). [승인된 상세 플랜](../backlog/playtest-improvements-plan-2026-09-10.html)과 [개선 목록](../backlog/playtest-improvements.md).

## 적용한 동작

| 항목 | 구현 |
|---|---|
| FB-001 추천·선택 | 추천은 옅은 황색 배지, 선택은 녹색 체크·현재 선택됨·테두리/배경. 시작·저장 CTA에 선택 상품명을 표시. 추천과 선택이 같으면 두 배지를 함께 표시. |
| FB-002 버튼 | 옵션 거래에 한정해 동일 너비 2열·최소 높이 76px·중앙 정렬. 절반/전액 금액 표시, 입력값과 일치할 때만 선택 표시. 최소 매수금액 미달은 비활성+사유. 입력과 선택 필드는 최소 높이 48px·글자 16px 이상. |
| FB-003 실행 가능 여부 | 기존 메뉴·순서를 유지하면서 실행 불가능한 카드에 이용 불가와 사유를 표시. 가능 조합 존재 여부로 메뉴 판정, 선택된 초안으로 상세 실행 판정. 현재 자금·보유분·주문으로 매번 재계산. |

- 설정의 미지정은 과거 저장 옵션으로 대체하지 않습니다. 창을 열 때 한 번 선택 초안을 초기화하고 카드·CTA·확정에 함께 사용합니다. 성향 밖 저장값은 추천으로 정리한 이유를 먼저 보여 줍니다. 설정 X/Esc는 초안을 저장하지 않습니다. 시작 단계에는 기존 미지정 시작 경로가 있습니다.
- 옵션 메뉴는 옵트인 또는 옵트아웃 중 하나라도 가능하면 열립니다. 환매만 가능하면 옵트아웃으로 진입합니다. 이미 입력한 금액·환매 비율은 포트폴리오 왕복·재접속에서 유지합니다.
- 대기자금이 없어도 직접 보유분 매도·교체가 가능합니다. 옵션 주문 대기는 옵션 거래를 막지만 가능한 직접 거래까지 막지 않습니다. 미결제 주문은 리밸런싱을 막고, 리밸런싱 매도 계획이 끝나 매수 주문만 남으면 잔여 자금·보유분으로 다시 판단합니다.
- 비활성 이유는 누르거나 마우스를 올리지 않아도 보입니다. 버튼에 실제 disabled 속성과 aria-describedby를 적용했습니다. 라디오 선택은 방향키·Home/End로 허용 카드 사이를 이동할 수 있습니다.
- 모바일 검증 중 발견한 X 버튼과 탭의 겹침은 운용/사전지정 창의 닫기 버튼을 별도 상단 영역에 배치해 수정했습니다. 추가 취소 버튼은 만들지 않았습니다.

## 구현 구조와 규칙 보존

`src/engine/action-constraints.ts`가 행동 시점, 리밸런싱 잠금, 추가납입 승인 금액, 리밸런싱 가능 자산, 옵션 거래 입력/보유 조건을 공통으로 제공합니다. 실행 엔진과 화면이 같은 조건을 사용합니다. 결과에는 enabled와 사유 코드/문구가 있으며 문자열 내용으로 조건을 추정하지 않습니다.

`src/engine/action-availability.ts`는 후보 상품과 허용 옵션을 확인해 메뉴가 열릴 수 있는지 계산합니다. 일반 매수의 위험한도 축소 확인은 유효한 진행 경로로 취급합니다. 매도·교체 상세는 순수 거래 함수를 이용해 실제 선택값을 검사합니다. 메뉴 조회에서 performAction을 호출하지 않으므로 턴 마감·점수·학습 기록이 생기지 않습니다.

일반 거래 최소 10만원과 옵션 내부 구성품/환매의 소액 예외를 구분합니다. 예금 약정, 결제 시점, 직접/옵션 출처, 상품별 성향·위험한도는 유지합니다. 완료된 판이나 남은 행동이 0인 상태에서의 재실행은 공통 시점 검사로 거절합니다. 관련 기존 테스트 두 개는 실제 플레이와 맞게 actionsLeft=1인 운용 시점으로 보완했습니다.

저장 키·c2/c3 스키마·C/D/E 규칙 버전은 바꾸지 않았습니다. 기존 판의 일반 메뉴와 기존 디폴트옵션 규칙은 유지하며 새 조건 안내를 적용합니다. 자동운용·연결 교체매수 등 [별도 P1 목록](../backlog/default-option-redesign.md)은 이번 범위에 포함하지 않았습니다.

## 검증

- 전체 Vitest 455개 / 42개 파일 통과. 추가 조건 검사, 실제 앱 클릭·포트폴리오 왕복·재접속·설정 미지정·키보드 선택·비활성 버튼 강제 이벤트·기존 저장 호환을 포함합니다.
- `npm run build`(TypeScript 포함), `npm run lint`, `git diff --check` 통과.
- `npm run verify:default`: 5,600판, 오류 0건. 4,400 기본 시뮬레이션과 1,200 옵션 부분 환매·혼합 출처·마지막 턴 등 확장 시뮬레이션.
- 실제 빌드의 인앱 브라우저에서 시작 선택 → 1턴 납입 → 2턴 옵션 금액 입력/포트폴리오 왕복/새로고침 → 전액 옵트인 → 3턴 주문 대기 메뉴 확인. 매수·리밸런싱·옵션은 사유와 함께 비활성, 직접 매도·교체·납입·마감은 유지됨을 확인했습니다.
- 320/375/390/430px에서 추천·선택 화면과 옵션 거래 화면의 가로 넘침 없음. 금액 버튼 양쪽 너비 동일, 높이 76px, 옵션 선택 필드 높이 48px 확인.
- 실제 옵션 거래 렌더러·CSS를 사용하는 별도 로컬 검증 페이지에서 루트 글자 크기 200%(32px), 320/390/430px 확인. 금액 버튼은 줄바꿈에 따라 높이가 늘어나며 버튼/창 가로 넘침 없음. 이는 브라우저 검증이며 iPhone 실기기 검증을 대신하지 않습니다.
