## D0 공통 디자인 기준

- 흰색 배경, 고딕 제목, 녹색 주요 버튼. 녹색 `#10833f`, 본문 `#263b2e`, 보조 글자 `#607267`, 선 `#d9e4dc`. 보조 카드에는 연한 민트·파랑·노랑을 쓴다.
- PC 콘텐츠 폭 1,040~1,120px. 선택/상세는 좌우 2열, 800px 이하에서는 DOM 순서대로 위아래 배치한다. 모바일 외곽 여백 16~20px, 기본 카드 모서리 16px, 주요 버튼 높이 54~56px.
- 선택됨: 라디오 표시·녹색 테두리·‘현재 선택됨’. 추천: 노란 ‘성향 추천’. 선택 불가: 실제 disabled 속성과 성향/등급 사유. 색만으로 상태를 전달하지 않는다.
- 입력·버튼·링크·펼침 메뉴에 키보드 포커스 표시를 유지한다. 기존 모달 포커스 가두기/복귀, X 닫기, 오류 문구와 거래 가능성 계산은 재사용한다.
- 제목/설명/캐릭터/시작 버튼 순서를 유지하며, 캐릭터·시나리오·주간 도전은 메인의 펼침 메뉴에 모은다. 진입 동의와 이어하기는 바로 보인다.
- 공통 색/버튼 토큰은 기존 하위 모달에도 적용된다. D2/D3 대상 화면의 정보 배치와 고유 상태 설명은 해당 단계에서 변경한다.
- 정산의 손익·입출금·매매 구분, 금리 %p, 위험비중 안내, 퀴즈 스킵 확인은 기존 엔진/뷰 값을 사용한다.

### 주사위 정확성

최근 결과는 `dicePairForTurn(seed, turn - 1)`로 이미 실행한 턴의 실제 두 눈을 표시한다. 별도 난수나 새 저장 필드를 추가하지 않는다. 다음 턴의 눈은 노출하지 않으며, 굴리는 동안 최근 결과를 숨긴다. 36개 조합의 점 눈·접근성 합계, 동작 줄이기/이어하기의 실제 이동 일치를 자동 검사한다. 연출 시간과 말 이동 제어 코드는 재사용한다.

### 이미지 실패

메인 이미지 아래에 주사위 표식과 제목 대체 UI가 있다. 이미지 실패는 현재 화면 세션에 기록해 동의/설정 변경 시 실패한 이미지를 반복 삽입하지 않는다. 캐릭터 표시를 끄면 대체 UI를 사용한다. 보드의 그림은 장식이며, 이미지 유무와 무관하게 칸·말·상태 텍스트는 SVG로 남는다.

## 검증

자동 검사: **57개 파일 / 598개 테스트 통과**, 타입 검사·린트·빌드 통과. 기존 디자인 비교용 정적 프로토타입(`docs/design`)은 애플리케이션 린트 대상에서 제외한다. 실제 `src`, 테스트, 빌드 스크립트에는 기존 검사를 적용한다.

Ego Browser(Chromium)에서 **PC 1440×1000 / 모바일 390×844 각각 12턴 완주**를 확인했다. 모바일은 2배속·일반 연출, PC는 동작 줄이기로 진행했다. 생활사건 → 운용 → 정산 → 퀴즈 스킵 안내 → 수령 방식 → 결과까지 연결됐고, 완료 저장은 지워지며 누적 플레이 수는 두 판 후 2가 됐다. 거래별 특수 조건은 기존 자동 검사로 확인하며, 이번 직접 플레이는 시작·보드와 전체 턴 연결에 초점을 맞췄다.

- 11턴에서 새로고침 → 이어하기 후 게임 전체 객체의 깊은 비교가 일치했다([기록](resume-qa.json)).
- 보드 밖 스크롤 1,513px에서 굴리기 → 보드 노출 → 실제 회전 → 1+3=4칸 이동과 최종 위치 일치. Web Audio 재생 호출과 설정의 효과음 테스트 응답을 확인했다. 실제 기기에서 귀로 들은 검증은 아니다.
- 옵션 화면 320/390/430/1440px에서 가로 넘침 없음. 844×390 가로 화면에서도 옵션 확인 버튼까지 스크롤 가능.
- 이미지 요청 실패를 주입해 대체 UI와 시작 진입을 확인했다.
- [검증 요약 JSON](validation-summary.json), [PC 클릭 기록](desktop-play.json), [모바일 기록](mobile-play.json), [반응형 측정](responsive-qa.json), [이미지 실패 확인](image-fallback-qa.json).
