## 버전과 저장 호환성

- 금융 규칙 `2026-09-15-f`, 스냅샷 `financeRules.version=f1`, 진행 저장 `c4`. 저장 키와 브라우저 로컬 저장 방식은 유지한다.
- 기존 c1/c2/c3는 원래 배분·대기 이자 0·기존 주문 규칙으로 이어 한다. 기존 판에 신규 자산 규칙을 소급 적용하지 않는다.
- 새 고스트·비교 지수·분기 연습은 해당 판의 초기 배분과 규칙을 사용한다. 구 분기를 새 규칙으로 바꾸지 않는다.
- 저장에는 이자율·초기 배분·마지막 반영 턴·기초 대기자금·실제 이자 금액을 검증한다. 버전 불일치·잘못된 금액·잘못된 분기 스냅샷은 거부한다.
- 재원별 수령 과세와 운용 성과 계산은 기존 엔진을 사용한다. 이자로 납입 원금을 늘리지 않는다.

## 자동 검사

- **62개 파일 / 647개 테스트 통과.** 기존 전체 테스트와 신규 금융 규칙 14개, 시작 경험·보조 화면 검사를 포함한다.
- 타입 검사·린트·프로덕션 빌드 통과.
- 잔액 0·원 미만·큰 금액, 납입 시점, 매수 예약·매도 결제, 같은 턴 재호출, 마지막 정산, 옵트인, 원금 재원, 정산 구성 합계, 고스트·분기·구 저장·손상 저장을 검증했다.
- 기존 UI 테스트 중 확인된 성향을 전제로 하는 항목에 진단 이력 fixture를 명시했다. 미진단 사용자의 별도 테스트를 추가했다.
- [첫 시장·12턴 계산 검사](finance-matrix.json): 실제 신규 엔진으로 공격투자형 네 시장 × 1,000개 시드의 첫 시장을 확인했다. 초과 0/4,000, 최대 위험비중 약 66.15~67.14%. 모든 후속 시장에서 초과하지 않는다는 보장은 아니다.
- 대기·납입 후 현금 유지·ETF 매수·리밸런싱의 네 전략 × 네 시장 × 100개 시드, **1,600판**을 완주하고 잔액·최종 주문·c4 복원을 확인했다. 납입 포함 IRP 총액과 운용지수를 따로 기록했다. 하락장에서 현금 유지가 유리할 수 있으며, 표본을 실제 이용자 승률이나 특정 전략의 보편적 우월성으로 해석하지 않는다.
- 재현: `node --import tsx scripts/verify-finance-rules.mjs`. 이 스크립트는 브라우저 플레이를 대체하지 않는다.

## 직접 브라우저 확인

Ego TaskSpace 6의 로컬 `localhost:5193` 테스트 탭을 사용한다. 운영 사이트의 저장은 변경하지 않는다.

- 모바일 Chromium 390×844·터치 에뮬레이션에서 미진단 안내 → 실제 5문항 클릭 → 공격투자형 결과 → 옵션 → 신규 판을 시작했다. 시작 구성이 35/20/45, 위험비중 65%였다.
- 다음 질문의 세 답안 테두리가 모두 기본색 `rgb(217, 228, 220)`이고 키보드 초점이 질문 제목에 있는 것을 DOM으로 확인했다. 실기기 iOS의 터치 hover 잔류 확인과 구분한다.
- 정상 모드의 첫 주사위에서 두 주사위 굴림 상태와 도착 후 결과 3칸·4번 칸 도착을 확인했다. 굴림·착지 애니메이션을 화면으로 관찰했다는 뜻은 아니다.
- Mac 잠금으로 스크린샷 도구가 시간 초과했으며 네이티브 도구에서도 잠금을 확인했다. 잠금 해제를 요청한 상태다. D3와 D4의 색·여백·주사위·말 이동 육안 확인, 실제 iOS Safari 키보드·터치·오디오 확인은 대기다.

- [모바일 12턴](mobile-play.json): 390×844 터치 에뮬레이션, 실제 포인터 입력으로 납입·옵트인·매수·매도·교체·리밸런싱·옵트아웃·퀴즈 스킵 확인·수령 확정·목표 미달 결과까지 67개 상태를 관찰했다. 1턴은 정상 굴림, 이후 동작 줄이기·2배속이다.
- [금융·주사위 대조](mobile-validation.json): 기록된 27개 체크포인트의 c4 복원과 게임 객체 깊은 비교, 66개 주사위 표시, 26개 정산 조회의 합계, 모든 턴의 이자 기초금액·이동 칸 일치. 같은 정산의 재조회도 포함하므로 26개의 서로 다른 턴을 뜻하지 않는다.
- [10턴 새로고침](mobile-resume.json): 금융 상태 전체·현재 이자 기록이 동일하다. 최초 JSON 문자열 비교는 객체 키 순서 차이로 실패하여 유효 검사에서 제외했다. 이후 의미상 깊은 비교가 일치했다.
- 12턴 리밸런싱 버튼 클릭 1회가 스크롤 도중 도구 타임아웃으로 끝났다. 다음 관찰에서 버튼 위치·클릭 지점과 미실행 상태를 확인한 뒤 실행했고 중복 주문 없이 완주했다. 앱 진행 오류로 단정하지 않는다.

- [PC 12턴](desktop-play.json): 배포된 `455cefd` Preview에서 1440×1000, 실제 키보드 Enter로 114개 상태를 확인했다. 관련 퀴즈를 풀고 수령을 확정했다. [47개 상태 복원·112개 주사위 표시 대조](desktop-validation.json)가 일치한다. 이후 두 보조 화면 보완(잠긴 목표 표시·미획득 대비/버튼 크기)은 로컬에서 별도 확인했다. 금융·게임 진행 규칙은 같다.
- [수령 비교 취소](payout-cancel.json): 연금 확정 후 일시금으로 임시 선택하고 취소해도 결과·설정 저장·완주 횟수 1회가 유지됐다.
- [보조 화면 조회](support-state.json): 유효한 c4의 6턴 완료 fixture를 설정·포트폴리오·타임라인·둘러보기에서 조회한 후 게임 객체 전체가 같다. 실제 완주 경로와 별도인 fixture 검사다. 최초 선택한 fixture에는 미해결 생활사건이 있어 조회를 진행할 수 없었으며, 완료된 6턴 상태로 교체했다.
- [구 저장 브라우저](legacy-browser.json): c3 판을 실제 새로고침·이어서 플레이로 불러와 전체 게임이 같고, 포트폴리오에 이전 무이자 규칙이 표시됨을 확인했다.
- [반응형 85회](responsive-qa.json): 17개 화면 상태 × 5개 크기에서 가로 넘침·누락된 접근성 참조·이미지 로딩 실패 0건. 초기 설정의 작은 옵션 버튼이 44px에 못 미치는 것을 찾아 수정하고, 미진단/게임 중 설정에서 44px를 재확인했다. 초기 측정도 기록에 남겼다. 도감 방향키·Home/End·탭 패널 연결과 [PC 진단 초점](diagnosis-browser.json)을 확인했다.
- 브라우저 자동화의 모호한 셀렉터와 스크롤 중 클릭 타임아웃은 실제 화면을 다시 관찰한 뒤 수정해 진행했다. 실패한 시도를 성공으로 집계하지 않는다. 화면 육안 확인과 실제 iOS Safari·가상 키보드·기기 오디오·200% 확대 확인은 여전히 대기다. 작업 종료 전 네이티브 도구로 Mac 잠금 상태를 다시 확인했다.
