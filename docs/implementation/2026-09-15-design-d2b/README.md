일반 주문은 현재 게임의 **금액 선택 버튼을 유지**한다. 시안의 자유 입력 예시를 새로운 일반 주문 기능으로 확장하지 않았다. 디폴트옵션의 기존 직접 금액 입력은 유지한다. 설정한 금액·상품에 해당하는 기존 엔진 결과를 미리보기로 읽으며 별도의 거래 계산을 만들지 않는다.

운용 메뉴·거래 화면의 X 취소는 행동을 쓰지 않는다. 포트폴리오 확인은 운용 화면 맨 아래에 한 번만 표시하며 조회 뒤 선택값과 스크롤 위치로 복귀한다. 일반 거래의 시장 상세는 주문 입력·확정 다음에 배치해 새 화면의 첫 내용을 주문에 집중하도록 했다. 시장 상세 내용과 펼침 상태는 유지한다.

## 합계와 출처

- 구성 그래프: 직접 운용 보유분 + 디폴트옵션 **보유분** + **전체 미결제** + IRP 대기자금 = IRP 평가액. 생활자금은 별도다. 그래프는 장식이며 같은 값을 문자·금액·비중으로 함께 제공한다.
- 기존 합산 보유 상품 표를 **직접 운용 보유 상품**으로 구분했다. 디폴트옵션은 별도 묶음 상세에 표시한다. 직접 미보유 상품에서도 기존 상품 위험·시장 예시를 확인할 수 있다.
- 옵션 묶음의 총액에는 해당 묶음의 미결제 주문이 포함될 수 있다. 실제 보유와 미결제 금액을 나눠 표시하고 계좌의 미결제 분류와 같은 금액임을 안내한다. 구성 그래프의 옵션 보유 항목에는 미결제를 다시 넣지 않는다.
- 전체 IRP의 규제 위험자산 비중과 기초 주식 노출을 구분한다. 시안의 예시 비중·금액·한도 문구를 실제 값으로 복사하지 않았다.
- 원금·시장 반영·거래·납입·주문 접수/가격확정/결제 엔진과 저장 스키마는 변경하지 않았다. 주사위·게임판 연출도 D2a 상태를 유지한다.

## 구현·상태 검증

- `order-layout.ts`: 일반 주문 공통 구조와 기존 `actionAvailability`를 사용하는 5종 탭. 비활성 탭의 사유는 버튼 밖에 남기고 접근성 설명으로 연결한다.
- `default-trade-view.ts`: 기존 draft/preview/command 경로를 유지한 분할 배치. 실패 미리보기와 확정 버튼의 설명을 연결한다.
- `portfolio-view.ts`: 겹치지 않는 네 분류와 직접 운용 상세. 합계 계산은 접어 두어 중복 표시를 줄인다.
- `dom-view.ts`: 선택상자의 명시적 선택값을 자식 갱신 전에 읽어 복원한다. 입력 중 DOM 검증에서 발견한 표시값 흔들림을 보완했다. 실제 Chromium에서도 입력·왕복 후 선택과 초안 일치를 확인한다.
- `design-d2b.css`: D2b 모달에만 배치·글꼴·입력·탭·카드 스타일 적용. PC 좌우, 800px 이하 위아래, 320px 좁은 화면의 탭 줄바꿈. 보조 설명·금액이 잘리지 않도록 최소 너비와 줄바꿈 처리.

전체 **59개 파일 / 617개 테스트**와 타입 검사·린트·프로덕션 빌드 통과. 명령: `npm test -- --maxWorkers=2`, `npm run typecheck`, `npm run lint`, `npm run build`.

추가 11개 검사는 일반 주문 5종의 화면 실행 결과와 엔진 전체 상태 일치, 포트폴리오 왕복, 전액 주문 후 비활성 탭, 한도 조정 재확인, 입력 노드·초점·검증, 스크롤 시 숫자 증감 방지, 여러 결제 상태에서 분류 합계의 일치를 확인한다.

## 직접 플레이 검증 기록

- [PC 12턴](desktop-play.json)과 [390×844 고정 화면 12턴](mobile-play.json)을 실제 UI 클릭으로 완주했다. 시작 준비, 납입·매수·매도·리밸런싱·교체, 생활 사건, 퀴즈 스킵 확인, 수령 선택과 최종 결과를 확인했다. PC는 매 행동 1440px, 모바일은 매 행동 390px임을 기록했다. 동작 줄이기·2배속 설정이며 새 주사위 연출 검사는 D2a 기록과 구분한다.
- [반응형 45건](responsive-qa.json): 일반 주문 5종·옵트인·옵트아웃·미결제 포함 포트폴리오·결제 완료 포트폴리오의 9개 상태 × 320×740, 390×844, 430×932, 844×390, 1440×1000. 모든 사례에서 가로 넘침 없음, 올바른 좌우/상하 배치, 비활성 사유 연결, 조회 전후 전체 게임 상태 일치. 320px는 좁은 CSS 뷰포트이며 실기기 검사가 아니다.
- 거래별 검증은 엔진으로 만든 정상 저장 사례를 브라우저에 불러온 뒤 UI로 확정하고, 기존 엔진이 계산한 전체 게임 상태와 비교한다. 실제 12턴 완주 기록과 별도의 사례 검사다.
- [개별 거래 대조](interaction-qa.json): 옵트인·옵트아웃·위험한도 조정 매수·12턴 TDF 매수가 모두 엔진 전체 상태와 일치. 한도 확인 단계에서는 거래하지 않았고, 최종 정산 일정에 가상 13·14턴을 약속하지 않는다.
- 실제 기기 Safari의 키보드·오디오는 D4에서 확인한다. 운영 주소는 변경하지 않았다.

모바일 직접 거래 검사에서 숫자 입력칸에 초점이 남은 채 휠 스크롤하면 브라우저가 금액을 증감하는 동작을 발견했다. 휠 스크롤 시작 시 숫자 입력의 초점을 해제하도록 보완했으며, 이후 옵트인 입력·조회·새로고침·복귀·확정과 옵트아웃 결과가 엔진 전체 상태와 일치했다. 일반 12턴 완주는 이 보완 전의 기록이며, 보완 후에는 관련 실제 거래와 전체 617개 테스트를 재검사했다.
