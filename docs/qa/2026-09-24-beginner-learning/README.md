| 02 | 선택형 첫 두 턴 실습: 돈 위치 → 상황별 조회·미리보기 → 직접 선택 | 1~2턴 운용 선택, 관련 포트폴리오·입력 화면 |

실습은 현재 `actionGuidance`의 가능한 선택을 읽는다. 생활자금 부족에서는 조회를, 주문·만기 대기에서는 해당 상태 확인을 우선한다. 실제 지시는 기존 확정 버튼으로만 실행한다. 중단·재시작·실습 완료·조회·X 취소는 행동이나 돈을 바꾸지 않는다. 실습 UI 진행은 기존 진행 저장의 선택 필드 `practice`에 분리하며 잘못된 안내 데이터는 버리되 금융 저장을 폐기하지 않는다. 2턴에는 최신 상태의 돈 확인부터 이어지고 3턴 이후 사라진다.

일반 포트폴리오 왕복의 스크롤 복원과 실습의 새 화면 진입을 구분했다. 실습에서 미리보기로 진입할 때 하단 포트폴리오 버튼으로 스크롤되던 문제를 직접 플레이에서 발견해 수정했다. 실습 안내의 제목에 포커스를 옮기고 상단부터 보여준다.

주문 일정은 실제 `PendingOrder` 필드에서 읽는다. 예금·ETF의 게임상 즉시 처리, 펀드 대기, 조건부 교체, 최종 정산을 구분한다. 조건부 연결 매수는 실행 조건을 다시 확인하는 예정임을 명시한다. 리밸런싱의 조건부 후속 매수는 실제 금액이 결제 시 결정되므로 기존 설명을 유지한다. 미래 수익을 예측하지 않는다.

만기 요약의 대상액은 각 활성 주기의 `remaining`이다. 주문 상태에서는 실제 미결제 금액, 포트폴리오에서는 보유분과 미결제를 나눠 보여준다. 서로 다른 만기·통지일·적용 예정일은 합치지 않는다. 처음 보여주는 통지는 위험·비용·실제 4주+통지 후 2주와 게임 단계 차이를 접지 않고 표시한다. 통지 표시 기록은 기존 엔진 처리 그대로이며, 펼쳐 보이지 않은 통지를 접힌 상세 때문에 확인한 것으로 처리하지 않는다. 만기 건별 기록·현금 유지 지시는 상세를 펼쳐 접근한다.

## Ego Browser 실제 플레이

운영 저장과 별개인 `http://127.0.0.1:5242/`에서 안정추구형/저위험 새 판을 직접 시작해 5턴까지 확인했다. 내부 게임 상태를 조작하지 않고 화면의 버튼으로 진행했다. 테스트용 localStorage는 읽어서 전후 비교했다.

1. 네 컷 안내, 5문항 진단, 사전지정, 실제 주사위 이동을 거쳐 1턴 실습 시작.
2. 돈 위치 조회·납입 미리보기·실습 완료·다시 보기는 시작 전 게임 객체와 동일. 수정 후 미리보기 진입 시 안내 제목 포커스와 스크롤 0 확인.
3. 별도 납입 실행으로 생활자금 13,400,000 → 12,400,000원, 대기자금 0 → 1,000,000원. 행동 1회 소모.
4. 2턴에 실습이 돈 확인부터 다시 시작. 단기채 상품 설명을 키보드 Enter로 펼치고, 1,001,000원 미리보기와 2턴 접수 → 3턴 가격 → 4턴 결제 확인.
5. 실제 매수 후 접수 단계 표시, 새로고침·이어 하기 후 게임 객체 동일. 3턴에 가격 확정 표시, 4턴에 해당 주문이 목록에서 제거됨.
6. 3턴부터 실습 없음. 성과급 중 200만원 납입, 예금 만기 65,869,200원은 별도 주기로 대기.
7. 4턴 자동운용 통지가 접히지 않고 노출, `presentedTurn=4`, `eligibleTurn=5`. 재조회에서는 새 통지를 중복 기록하지 않음.
8. 5턴 만기자금 66,001,004원 자동운용: 예금 46,200,702원은 보유, TDF 19,800,302원은 5턴 접수/6턴 가격/7턴 결제. 새로 납입한 200만원과 그 대기 이자는 IRP 현금에 남음.
