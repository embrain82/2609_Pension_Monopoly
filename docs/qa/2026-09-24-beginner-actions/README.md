## 구현

첫 운용 화면은 상태 힌트 하나, 가능한 목적 카드 최대 두 개, 그대로 마감, 전체 운용 보기로 구성한다. 목적 카드는 기존 거래 미리보기 또는 포트폴리오의 해당 위치를 열며 주문을 확정하지 않는다. 전체 메뉴는 기존 카드 디자인·비활성 사유·X 취소·포트폴리오 왕복을 유지한다. 다음 턴은 쉬운 선택으로 시작한다.

힌트는 생활자금 부족 → 현재 위험비중 초과 → 리밸런싱 잠금 → 만기 대기 → 미결제 주문 → 일반 운용 순으로 판단한다. 메뉴와 동일한 `actionAvailability`를 사용하며 첫 지시 후 최신 잔액으로 재계산한다. 미래 시장·수익 예측은 사용하지 않는다.

생활자금의 성향별 안전 기준은 기존 게임 기준이다. 기본 납입 초안이 그 기준을 넘겨 생활자금을 줄이면 짧은 목적 목록에서는 제외하되 전체 메뉴의 납입 제한은 바꾸지 않는다. 기존 IRP 대기자금으로 예금을 사는 것만으로 위험비중이 낮아진다고 설명하지 않는다. 같은 오해를 유발하던 거래 거절 문구도 수정했다.

그대로 마감 설명은 기존 주문과 만기 통지·대기·자동운용이 계속될 수 있음을 알린다. 기존 저장에서 마감이 지정옵션 직접 매수를 수행하는 경우 버튼에도 이를 표시한다. 만기 통지 원문은 접히지 않은 상태로 유지한다. 조회는 거래·행동을 만들지 않지만 최초 통지 표시는 기존 규칙대로 기록된다.

주사위·금융 계산·행동 횟수·점수·도장·저장 형식은 유지한다. 나머지 제안 02·04·07·08·09·10은 이번 범위가 아니다.

## Ego Browser 직접 플레이

운영 저장과 분리된 localhost에서 안정추구형 새 판의 2턴을 진행했다.

1. 네 컷 안내 → 5문항 → 성향 확인 → 저위험 사전지정 → 시작 → 실제 주사위 이동.
2. 첫 턴 대기자금 0원에서 힌트·목적 카드가 표시된다. 전체 메뉴에서 매수/옵션의 선택 불가 사유를 확인하고 쉬운 선택으로 돌아왔다.
3. 추가납입 목적 카드 → 미리보기 → X 취소 → 재진입까지 게임 상태가 불변임을 비교했다. 100만원 확정 후 생활자금 13,400,000 → 12,400,000원, IRP 대기자금 0 → 1,000,000원으로 일치한다.
4. 두 번째 턴 생활사건을 생활자금으로 해결한 뒤 힌트가 「IRP 안에 운용할 대기자금이 있어요」로 바뀌고 매수·추가납입 목적 카드가 표시된다.
5. 매수 카드로 단기채 1,001,000원을 주문했다. 대기자금 0원 / 처리 중 1,001,000원, 접수 2턴·가격 3턴·결제 4턴이다. 새로고침 → 이어하기 후 게임 객체가 동일했다. JSON 문자열의 키 순서가 정규화되어 달라지므로 구조적으로 비교했다.
