## 적용 내용

1. 첫 새 판 준비에서 성향 확인보다 먼저 주사위 → 시장 확인 → 행동 선택 → 결과 확인을 보여준다. 도착한 상품을 반드시 살 필요가 없다는 점과 행동 횟수·조회/취소 규칙을 짧게 설명한다. 시작 준비와 설정에서 다시 볼 수 있다. 기존 상세 규칙은 펼쳐 읽는다.
2. 포트폴리오에 생활 지갑 / IRP 대기자금 / 보유상품 / 처리 중 금액을 표시한다. 추가납입과 일반·디폴트옵션 거래 미리보기에도 동일한 그림을 사용하며, 확정 직후 바뀔 위치와 금액을 강조한다. 미리보기는 기존 엔진 결과를 읽으며 별도 주문을 실행하지 않는다.
3. 만기자금은 대기자금의 부분합으로 안내한다. 미결제 금액은 보유상품과 중복해서 더하지 않는다. 매도와 생활자금 인출을 구분한다.
4. 기존 `howtoSeen`은 과거 시작 흐름에서 자동으로 켜진 값일 수 있어 새 `quickGuideSeen` 표시를 사용한다. 기존 판 이어하기를 가로막지 않고, 준비 중 취소하면 기존 판과 설정을 보존한다. 안내 확인은 최종 시작 때 저장한다.

주사위, 시장·금융 엔진, 행동 횟수, 점수·도장, 미션 조건은 변경하지 않았다. 안내의 “30초”는 읽기 설계 목표이며 실제 초보자 이해도나 소요 시간을 측정한 결과가 아니다.

## 자동 검증

- 전체 테스트: **71개 파일 / 725개 통과**.
- 명령: `npm test -- --reporter=dot --maxWorkers=2 --testTimeout=20000`.
- `npm run lint`, `npm run build`(TypeScript 검사 포함), `git diff --check` 통과.
- 최초 전체 실행에서는 기존 대규모 만기 시뮬레이션이 5초 제한을 초과했다. 해당 테스트 단독 실행과 위 전체 재실행 모두 통과했다. 테스트의 검증 조건을 약화하지 않았다.
- 새 테스트: 안내 → 진단 → 시작, 기존 저장 호환성, 준비 취소, 안내 다시 보기, 미리보기 무변경, 납입·즉시 매수·펀드 매수/환매·교체·디폴트옵션 주문·결제 후 회계 일치, 만기자금 부분합.

## Ego 브라우저 직접 확인

운영 주소와 분리된 localhost 저장공간에서 새 판을 만들고 공격투자형 경로의 2턴을 진행했다.

- 첫 안내 네 컷 → 5문항 진단 → 옵션 확인 → 게임 시작.
- 첫 턴 100만원 납입: 생활자금 13,400,000 → 12,400,000원 / IRP 대기자금 0 → 1,000,000원. 미리보기와 실제 실행이 일치한다.
- 납입 화면을 X로 취소했을 때 게임 상태(잔액·행동 포함)가 그대로임을 비교했다.
- 두 번째 턴 단기채 펀드 매수: 이자 반영 대기자금 1,001,000원 → 처리 중 1,001,000원. 보유상품은 110,288,644.20381337원으로 유지되고, 주문은 2턴 접수 / 3턴 가격 / 4턴 결제다. 그림과 원장·미리보기가 일치한다.
- 새로고침 후 이어하기에서 2턴, 해당 미결제 주문과 돈의 위치가 그대로 복원된다.
- 320px·390px에서 돈 흐름 그림 내부 가로 넘침이 없음을 DOM 치수로 확인했다. 390px 새 판 안내는 네 컷과 진행 버튼이 844px 화면 안에 들어온다. 데스크톱 거래 미리보기에서도 내부 가로 넘침이 없었다.

근거: `contribution.json`, `fund-order.json`, `layout-320.json`, `layout-390.json`.

### 검증 한계

Ego의 `Page.captureScreenshot`이 반복해서 시간 초과되어 픽셀 캡처 검수는 완료하지 못했다. 화면 배율 에뮬레이션이 입력 뒤 바뀌는 경우가 있어 치수 검사는 반환된 실제 너비로 기록했다. 실제 iPhone/Safari 및 초보자 사용자 테스트는 수행하지 않았다. 이 기록을 모든 성향·시장 경로의 사용성 검증으로 해석하지 않는다.
