01. 이번 구현의 범위

우선 한 번에 출시할 범위

  • 단일 메뉴와 2단계 거래 화면
  • 옵트인: 지정 또는 선택한 옵션 직접 매수
  • 옵트아웃: 보유 옵션 일부·전체 환매 → IRP 대기자금
  • ‘이번엔 그대로’는 신규 주문 없이 턴 마감
  • 출처별 잔고, 미결제 주문, 취소·복귀, 저장 호환
  • D 복기·성과·학습 문구와 회귀 검증

이후 별도로 확장할 범위

  • 만기 자금 판별 → 통지 → 대기기간 → 자동운용
  • 옵트아웃 환매대금으로 다른 상품 연결 매수
  • 옵션 A에서 B로 결제 후 자동 교체
  • 여러 옵션 동시 보유·사업자별 세부 운영 차이

먼저 직접 거래 흐름을 완성합니다. 자동운용과 교체까지 한 화면에 넣으면 이전에 줄이려던 선택지가 다시 늘어납니다.

개발은 순차적으로, 출시는 하나의 완성된 흐름으로.

잔고 구조부터 바꾸고 거래와 UI를 붙인 뒤 통합 검증합니다. ‘그대로’의 매수 기능만 먼저 없애거나 옵트인만 공개하는 중간 배포는 하지 않는 안입니다.

02. 지정·옵트인·옵트아웃을 구분하기

개념의미게임에서의 처리
사전지정향후 제도의 적용 요건을 충족했을 때 사용할 운용방법을 선택설정값 저장. 즉시 매수하거나 기존 자산을 바꾸지 않음
옵트인자동 적용 대기 없이 디폴트옵션 상품을 직접 매수선택한 금액을 주문. 펀드 가격확정·결제는 별도 진행
옵트아웃디폴트옵션 운용 자산을 매도하여 다른 운용으로 전환해당 옵션 보유분 일부·전체 환매. 첫 버전은 대기자금으로 전환
자동운용적용 대상 자금에 운용지시가 없고 통지·대기 요건을 충족했을 때 실행별도 단계. 이번 직접 거래 화면의 실행 조건으로 사용하지 않음

산업은행은 직접매수와 매도를 옵트인·옵트아웃으로 설명하고, 등록/변경과 직접매매 진입점을 구분합니다. 매도 시 포트폴리오에 포함된 예금의 중도해지이율이 적용될 수 있습니다. [1]

‘옵트아웃 = 지정 해제’ 또는 ‘자동운용 OFF’로 표시하면 안 됩니다. 현재의 지정값 삭제는 이미 산 자산을 환매하지 않습니다. 새 화면에서도 거래 완료와 사전지정값 변경은 서로 다른 결과입니다.

기존 상품 만기 후 자동 적용은 4주 경과 시 통지, 통지 후 2주 동안 별도 운용방법을 정하지 않는 절차가 있습니다. 신규 가입과 만기 자금의 조건도 구별해야 합니다. D의 1턴은 가상 3개월이므로 ‘4주 = 4턴’으로 구현할 수 없습니다. [2]

04. 거래별 상세 계약

항목옵트인옵트아웃
거래 대상선택한 디폴트옵션 전체 구성해당 옵션 출처로 보유한 자산만
입력절반 / 전액 / 직접 입력. 기본은 절반, 확정 전 미리보기50% / 100%. 금액은 현재 평가액 기준 예상값
자금사용 가능한 IRP 대기자금. 생활자금·미결제 환매대금은 사용 불가결제 시 IRP 대기자금에 반영. 계좌 밖 인출이 아님
구성 유지명시된 신규 매수 비중으로 분할. 소액이라고 첫 상품에 몰아주지 않음구성 상품의 매도 가능한 수량에 같은 환매 비율 적용. 특정 구성품만 선택 불가
최소 금액묶음 주문 최소 10만원을 게임 규칙으로 유지. 구성품 내부 분할에는 별도 10만원 최소를 적용하지 않음소액 잔액도 전체 환매 허용. 수량·원 단위 반올림 잔여 처리 명시
행동 차감거래 묶음 접수 성공 시 1회. 입력·취소·실패·결제 진행은 0회. 행동 2회 칸에서는 접수 후 1회 남음
가격·결제공통 엔진의 상품별 일정 사용. 펀드는 접수 턴 t → 기준가 t+1 → 결제 t+2. 실제 금융상품 영업일 규칙과 다른 게임 시간임을 표시
비용선택한 구성품의 기존 보수·수수료만 적용. 묶음이라는 이유로 별도 중복 과금하지 않음예금은 해당 출처의 약정만 부분 해지하고 약정별 중도해지 조건 반영
완료 후 지정자동으로 바꾸거나 해제하지 않음. ‘사전지정’과 ‘현재 보유’는 각자 표시

포트폴리오형 옵션을 구성품별로 쪼개 매도하지 않는 설계는 KB증권의 실제 운영 안내를 참고했습니다. 비율 환매는 시장 변동 후 보유 수량에 같은 비율을 적용하는 것이며, 최초 매수 목표비중으로 다시 맞추는 리밸런싱이 아닙니다. [3]

게임의 단순화: 최초 버전은 한 종류의 옵션만 보유·주문할 수 있게 합니다. 보유 중이면 같은 옵션만 추가매수하고, 전부 환매·결제한 뒤 다른 옵션을 매수합니다. 실제 사업자별 복수 보유 처리까지 보편적 법칙으로 설명하지 않습니다.

핵심 예시

직접 매수한 TDF 300만원과 중위험 옵션 400만원(혼합형 200만원 + TDF 200만원)을 가진 경우, 50% 옵트아웃은 옵션의 혼합형·TDF 각 절반만 환매합니다. 직접 매수 TDF 300만원은 유지됩니다.

200만원은 현재 평가액 기준 예상치입니다. 실제 IRP 대기자금 반영액은 가격확정과 비용에 따라 달라지고, 그동안 중복 사용하지 못합니다.

06. 엔진과 데이터 설계

A. 상품별 총액 안에 운용 출처를 기록

현재 Holding과 PendingOrder에는 디폴트옵션 매수 출처가 없습니다. portfolio-engine.ts는 같은 productId를 하나로 합칩니다. 출처 없이 옵트아웃을 넣으면 직접 산 TDF까지 환매하는 문제가 생깁니다.

권장 구조는 상품별 Holding을 유지하면서 내부에 출처별 position을 두는 방식입니다. 같은 상품 ID의 Holding을 여러 개 추가하면 현재의 .find(productId) 사용 지점이 첫 잔고만 읽을 수 있습니다.

출처별 포지션을 유일한 잔고 원본으로 삼고 상품별 총액은 공통 함수에서 합산합니다. 호환용 총액 필드를 남기더라도 직접 수정하지 않고 원본에서 다시 계산합니다. 주문 묶음이나 옵션 요약 금액을 자산총액에 한 번 더 더하지 않습니다.

시장 수익·보수·가격확정·부분 환매·예금 약정·적격 중도인출 모두 공통 잔고 변경 함수를 거쳐야 합니다. 옵션 보유/주문 잔액이 모두 0이면 종료된 운용 단위로 기록합니다. 현재 예금은 만기 이후 자동 상환되지 않고 잔고를 유지하므로, P0에서는 이 동작을 유지합니다. P1에서 자동 상환을 구현할 때 포지션 제거와 현금 반영을 한 번의 거래로 처리합니다.

생활사건 청산 순서: 기존 결제 현금 → 직접 운용 예금·ETF → 모든 구성품이 즉시 결제 가능한 옵션의 비율 환매 순서로 검토합니다. P0의 펀드 혼합 옵션은 생활비를 즉시 마련하기 위해 구성품 예금만 따로 팔지 않습니다. 즉시 결제 자금이 부족하면 기존 생활비 분할 지급 흐름을 안내하고, 펀드 결제를 기다려야 한다는 이유를 표시합니다. 예금만 현금화하는 선택지는 직접 운용 예금과 예금 100% 옵션만 대상으로 합니다. 이 청산은 생활사건 해결에 포함하며 운용지시 행동을 추가 차감하지 않습니다.

B. 미리보기와 실행이 같은 거래계획 사용

  1. previewDefaultOptIn(state, optionId, amount) 또는 previewDefaultOptOut(state, mandateId, fraction)이 읽기 전용 계획을 생성합니다.
  2. 현금·출처별 수량·성향·옵션 구성·관련 주문·비용·한도를 묶음 전체 기준으로 검사합니다. 계좌 전체의 예약현금과 리밸런싱 계획도 검사하고, P0에서는 리밸런싱 처리 중 옵션 지시를 막습니다. 반대로 리밸런싱 접수도 진행 중 옵션 주문과 자금 충돌을 검사합니다.
  3. 확정 시 상태 버전을 확인하고 같은 검증을 다시 실행합니다. 변동됐으면 미리보기를 갱신하여 재확인합니다.
  4. 임시 상태에서 모든 구성품 주문을 만든 후 전체 성공일 때만 상태를 교체합니다. 한 상품만 매수되고 다른 상품은 누락되는 접수는 허용하지 않습니다. 내부 구성품의 최소금액 예외와 거래 잠금 우회 권한은 분리합니다. 기존 internal=true를 그대로 재사용해 리밸런싱 잠금까지 우회하지 않습니다.
  5. 고유한 commandId로 재클릭·복원 시 중복 주문을 차단하고, 행동은 묶음당 1회 차감합니다.
  6. 접수 후 개별 구성품은 기존 상품별 일정으로 결제합니다. ‘일부 결제’와 ‘완료’를 묶음 상태로 보여줍니다. 일부 결제는 접수 실패와 다른 정상 진행 상태입니다.

새 게임 행동은 default-opt-in, default-opt-out으로 명시합니다. 순수 함수와 읽기 전용 미리보기를 유지하고, UI에서 현금·잔고를 직접 수정하지 않습니다.

C. 승인 포트폴리오 규칙과 경제적 위험을 분리

현재 4개 옵션은 일반 상품을 나열한 교육용 묶음이며 고위험형에는 주식 ETF가 들어 있습니다. 이 데이터만으로 실제 승인 상품이라고 할 수 없습니다. 법령상 운용유형·승인 구조와, 승인 사전지정운용방법에 적용되는 규제 분류를 구별해야 합니다. [2] [4]

  • 구현 첫 단계의 필수 산출물: 옵션별 명시적 구성비·가상 위험등급·원리금보장 여부·적격 유형 가정·제도 근거·검수일·버전. ETF를 섞은 현 고위험안을 곧바로 승인 포트폴리오로 취급하지 말고 TDF/BF형 학습 모형으로 재구성합니다. 구체 배분과 등급은 이 데이터 검토에서 확정합니다.
  • 교육용 모형 표시: ‘승인 제도 구조를 설명하는 가상 상품’이라고 표시합니다. 실제 승인받은 상품명이나 승인을 받았다는 문구는 사용하지 않습니다.
  • 한도 계산: 검수된 옵션 운용 문맥에서 승인유형 예외를 모사합니다. 일반 매수 ETF나 같은 펀드 전체에 예외가 전파되지 않도록 출처·옵션 버전을 기준으로 판단합니다.
  • 성향 적합성: 포트폴리오의 검수된 가상 위험등급으로 판단합니다. 규제상 편입한도 예외와 원금보장·개인 성향 적합성을 같은 개념으로 취급하지 않습니다.
  • 실제 주식 노출: 옵션 구성품까지 합산해 D 위험 설명·전망·낙폭에 반영합니다. 규제상 위험자산 계산에서 예외라고 손실위험이 0이 되지는 않습니다.

이 검수가 끝나지 않은 가상 묶음에 예외를 켜지 않습니다. 사용자 화면보다 먼저 고정할 데이터 계약이며, 개별 상품의 기존 위험값을 일괄 변경하는 방식은 피합니다.

D. 기존 저장과 분기 복원

과거 동일 상품 잔고의 직접 매수분과 옵션 매수분을 텍스트 로그만으로 정확히 복원하기는 어렵습니다. 기존 C/D 판을 강제 변환하지 않고 새 판부터 새 규칙을 적용하는 안을 권장합니다.

  • 체크포인트·규칙 버전을 명시하고 버전별 파서와 거래 동작을 분리합니다. 새 필드를 기존 게임 생성 결과로 일괄 검사하면 옛 저장이 거부될 수 있습니다.
  • D의 3·6·9턴 분기에도 당시 옵션 버전·출처·미결 주문을 저장합니다. 기존 분기는 당시 규칙으로 다시 시작합니다.
  • 새로고침 시 미확정 초안은 검토 화면으로 복원하지만 주문을 자동 실행하지 않습니다. 접수 후 저장은 확정된 주문 ID로 복원합니다.
  • 기존 모드의 상품 구성도 버전별로 보존해야 합니다. 공용 JSON만 바꾸면 이전 판의 추천·hold 실행 결과까지 바뀔 수 있습니다.

09. 반드시 통과해야 할 시나리오

  1. 메뉴 단순성: 첫 화면 디폴트옵션 관련 행은 정확히 하나. X만으로 보드에 복귀 가능.
  2. 미확정 무변경: 탭·금액 변경, 뒤로, X/Esc, 포트폴리오 왕복 전후 자산·행동 횟수 동일.
  3. 출처 분리: 같은 TDF를 직접 운용·옵션 운용으로 함께 보유한 상태에서 옵션분만 환매.
  4. 부분/전체: 50%·100% 환매 후 모든 구성품 수량과 원금 기록 일치. 소액 잔여 청산 가능.
  5. 소액 매수: 10만·15만원도 명시 비중 유지. 첫 상품으로 몰아주는 분기 없음.
  6. 주문 실패: 한도·성향·잔액·구성 검증 실패 시 일부 주문·현금 차감·행동 소비 없음.
  7. 한도 문맥: 승인유형 학습 예외는 해당 옵션 출처에만 적용. 같은 일반 상품·일반 ETF에 전파되지 않음.
  8. 대기자금: 예약 현금·미결제 환매대금·생활자금 사용 불가. 총자산에 주문 금액 중복 합산 없음.
  9. 중복 실행: 더블클릭과 접수/가격확정/결제 단계 새로고침 후 중복 주문·수익·차감 없음.
  10. 행동 2회 칸: 옵션 구성품 수와 무관하게 1회 차감. 순수 마감은 남은 행동 종료.
  11. 약정 보존: 서로 다른 금리·만기의 직접 운용 예금과 옵션 예금 중 대상 lot만 해지.
  12. 일반 거래: 일반 매도·교체·리밸런싱이 옵션 구성품을 임의로 환매하지 않음. 자동 청산과 만기도 장부 동기화.
  13. 수익 계산: 매수·환매만으로 외부 납입·세액공제·순입출금 증가 없음. 비용만 D 성과에 반영.
  14. 마지막 턴: 12턴 신규 주문을 추가 급여·시장 수익 없이 끝까지 결제. 미결 주문과 잠금이 남지 않음.
  15. 저장 호환: 기존 C/D 진행·3/6/9턴 분기와 새 버전 분기 모두 각 규칙으로 복원.
  16. 교육 일치: 지정 해제가 옵트아웃이라는 문장 없음. 즉시 주문과 즉시 결제, 환매와 인출을 구분.
  17. 게임성: 옵션 거래 반복만으로 점수 획득 불가. 옵션 보유·직접 운용·혼합 전략의 미션 성과 비교.
  18. 브라우저: 데스크톱·390px 화면, 키보드 포커스·Esc·미결제 알림·포트폴리오 복귀 확인.

기존 테스트·빌드·린트와 D 매트릭스를 재실행하되, 기존 11전략 외에 ‘일부 옵트아웃’, ‘직접/옵션 동일 상품 혼합’, ‘마지막 턴 주문’ 전략을 추가해야 새 기능을 검증할 수 있습니다.

10. 자동운용을 나중에 붙일 때의 경계

자동운용은 ‘이번엔 그대로’를 누르는 순간의 부수 효과로 다시 넣지 않습니다. 대상 자금의 발생 사유·시점과 통지 기록을 가진 별도 이벤트로 처리해야 합니다. 직접 환매해 대기 중인 자금이 다음 턴에 다시 옵션으로 들어가는 순환도 막아야 합니다.

D의 가상 분기 달력 안에서 주 단위 통지·대기 이벤트를 계산하거나, 교육용 단계를 명시하는 별도 시나리오를 설계합니다. 최초 가입, 기존 상품 만기, 자발적 환매, 추가납입을 같은 ‘현금 잔액’ 조건으로 처리하지 않습니다. 자동운용을 구현하기 전에는 시작·설정·도움말에서 이번 버전의 체험은 직접매수/환매 중심이라고 일관되게 설명합니다.
