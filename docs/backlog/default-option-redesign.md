# 디폴트옵션 거래 메뉴 재설계

상태: P0 구현 완료 · v1.5.0 · 2026-09-10 사용자 승인에 따라 별도 구현

설계 기록: [디폴트옵션 옵트인·아웃 구현 제안 및 화면 시안](default-option-implementation-proposal.html). 시안은 상세 창의 정보 구성을 설명하기 위한 것이며 기존 메뉴 디자인을 축소하지 않습니다. 최종 구현과 검증은 [v1.5.0 기록](../implementation/2026-09-10-default-trading.md)을 기준으로 합니다.

문제: 운용하기의 옵트인·옵트아웃·현재 현금 유지 선택지가 첫 화면을 복잡하게 만듭니다. v1.2.1에서는 추가 UI 및 관련 자동운용 구현을 단계 A로 복원했습니다.

## P0 완료 범위

1. 운용지시 메뉴에는 「디폴트옵션 옵트인/아웃」 진입점 하나만 표시합니다.
2. 별도 창에서 옵트인(직접 매수)과 옵트아웃(보유분 환매)을 설명과 함께 구분합니다. 사전지정 변경·해제는 거래와 별도로 처리합니다.
3. 현재 지정 상품·대상 금액·미결제 주문을 보여 주고 선택 결과를 미리 확인합니다.
4. X/Esc로 닫으면 자산과 행동 횟수는 바뀌지 않고 보드로 돌아갑니다. 하위 창의 뒤로 이동은 운용 메뉴로 복귀하며, 별도의 '취소하고 보드로' 버튼은 추가하지 않습니다.
5. 기존 여섯 카드의 디자인과 순서를 유지하고 「이번엔 그대로」 위에 새 카드 하나를 추가했습니다. 하위 화면에서만 옵트인·아웃을 구분합니다.
6. 직접 보유분과 옵션 보유분의 출처 장부를 분리했습니다. 옵트아웃은 보유분 50% 또는 전부를 구성품마다 같은 비율로 환매하며 일반 보유분을 건드리지 않습니다.
7. 새 판의 「이번엔 그대로」는 새 주문 없이 턴을 마칩니다. 기존 저장 판은 C/D 규칙을 유지합니다.
8. 금액·비용·결제 미리보기, 중복 주문 방지, 한 행동 차감, 포트폴리오 왕복과 초안 복원, D 복기·분기를 연결했습니다.

## P1 후속 검토 (이번 구현에서 제외)

- 사전지정에 따른 자동운용: 신규 가입·기존 상품 만기 자금을 구분하고 통지·대기 상태를 게임 시간에 표현하는 방법. 현재는 명시적 옵트인 거래만 실행합니다.
- 옵트아웃 후 다른 일반 상품으로 연결 매수하는 다단계 거래. 현재는 결제 후 IRP 대기자금으로 받습니다.
- 둘 이상의 디폴트옵션 동시 보유·옵션 간 교체. 현재는 한 종류 보유, 같은 옵션 추가 매수, 전량 환매 결제 후 다른 옵션 선택입니다.
- 실제 초보자에게 지정·매수·환매 차이와 두 단계 메뉴가 이해되는지 사용성 검증.

## 검증 기록

433개 테스트, 빌드·타입 검사·린트 통과. 5,600판 자동 플레이에서 종료·결제·출처 장부 오류 0건. 새 규칙은 `2026-09-10-e`, 진행 저장은 `c3`입니다. B 완료 범위는 투자자성향·캐릭터 분리로 유지하고 이번 작업은 별도 확장으로 기록합니다.
