추천 상품과 현재 선택한 상품

현재 상태와 문제

renderDefaultOptionCards는 추천 배지와 선택 상태를 따로 계산합니다. 다만 선택은 배경·테두리로만 드러납니다. 추천 배지도 녹색이고 hover도 테두리를 강조하므로 모바일에서는 서로 다른 상태가 비슷하게 보일 수 있습니다.

화면 변경안

  1. 성향 추천: 작은 옅은 황색 배지만 표시합니다. 추천만으로 카드 전체를 강조하지 않습니다.
  2. 현재 선택: 라디오 체크 + 「현재 선택됨」 문구 + 녹색 테두리·배경을 함께 표시합니다.
  3. 추천과 선택이 같으면: 두 표시를 모두 보여 줍니다. 추천 표시를 선택 표시로 대체하지 않습니다.
  4. 확정 버튼: 「원리금보장형으로 시작」처럼 실제 선택 상품명을 넣습니다. 설정에서는 「원리금보장형으로 저장」으로 표시합니다.
  5. 키보드 포커스: 바깥 주황색 outline으로 구분합니다. hover는 배경을 약하게 바꾸며 선택용 테두리를 재사용하지 않습니다.

선택값을 한 곳에서 관리

창을 열 때 유효한 현재 지정값·저장값·추천값을 기존 우선순위에 맞게 확인해 선택 초안을 한 번 초기화합니다. 카드 체크, 요약 문구, 확정 버튼, 실제 저장은 모두 이 초안을 참조합니다. 렌더와 확정에서 각각 다른 fallback을 계산하지 않게 합니다.

현재 추천은 5개 성향 모두 신·구 규칙에서 같지만, 호출 시 규칙 버전을 명시합니다. 허용 밖 저장값은 창을 여는 시점에 정리하고 사유를 안내해, 확정 순간 보이지 않던 상품으로 바뀌지 않게 합니다.

명시적 미지정: 설정의 현재 값이 「지정 안 함」이면 과거 저장값으로 덮어쓰지 않습니다. 최초 추천 표시를 위한 미초기화 상태와 사용자가 선택한 미지정 상태를 구분합니다. 「지정 안 함으로 시작」·「지정 해제」 경로는 유지합니다.

변경 파일: src/ui/default-option-view.ts, src/ui/app.ts, src/styles/main.css. 필요한 초안 해석 함수는 UI 보조 함수로 추가합니다.

현재 코드에서 확인한 원인

공통 .amount-presets는 repeat(3, 1fr)인데 디폴트옵션에는 버튼이 두 개입니다. 그래서 오른쪽이 비고 버튼 폭이 좁습니다. 버튼은 grid이지만 콘텐츠 중앙 정렬·명시적 내부 여백도 부족합니다. 금액 입력과 달리 상품 선택 select에는 전용 크기 규칙이 없습니다.

디자인 규격

  • 금액 선택: 디폴트옵션 전용 2열, 두 버튼 동일 너비, 간격 10px. 최소 높이 76px에 라벨·금액을 두 줄로 중앙 정렬합니다.
  • 입력·상품 선택: 글자 16px 이상, 최소 높이 48px, 모서리 12px, 내부 여백 12~14px로 통일합니다.
  • 옵트인/아웃: 2열 유지. 활성 탭은 녹색 바탕·흰 글자, 비활성 탭은 회색 바탕과 사유로 구분합니다.
  • 버튼 역할: 확정은 채운 녹색, 금액 프리셋은 테두리 버튼, 뒤로 이동은 텍스트 버튼으로 구분합니다.
  • 선택 상태: 금액이 프리셋과 일치할 때만 선택 강조와 aria-pressed를 켭니다. 다른 금액을 직접 입력하면 프리셋 강조를 해제합니다.
  • 좁은 화면: 320/375/390/430px에서 확인합니다. 글자 확대 시 높이는 늘어나며 텍스트를 잘라 내지 않습니다.

공통 3개 금액 버튼은 유지하고, 디폴트옵션 영역에만 .default-trade-presets를 붙여 2열을 적용합니다. 전체 버튼 CSS를 일괄 변경하지 않습니다.

선택할 수 없는 운용지시는 이유부터

버튼을 숨기지 않고 비활성화합니다. 기존 카드의 이름·설명을 유지하고, 제한된 카드 아래에 짧은 사유를 추가합니다. 이 판정은 두 번째 행동뿐 아니라 운용 화면이 열릴 때마다 현재 상태를 기준으로 적용합니다.

현재 첫 화면의 「선택」 버튼에는 실행 조건이 연결되어 있지 않습니다. 하위 화면도 일부 조건만 확인해, 예를 들어 리밸런싱 매도 정산 중에 일반 매도 버튼이 활성화된 채 엔진에서 거절될 수 있습니다. 첫 화면과 하위 확정 버튼이 같은 판정 근거를 쓰게 합니다.

대기자금 0원 ≠ 모든 행동 불가. 직접 보유 상품은 매도·교체할 수 있고, 미결제 주문이 없다면 보유분을 팔아 리밸런싱할 수도 있습니다. 디폴트옵션 보유분이 있으면 옵트아웃은 가능할 수 있습니다. 메뉴 하나의 특정 상품·금액이 실패한다는 이유로 전체 메뉴를 막지 않습니다.

옵트인은 성향에 맞는 옵션·10만원 이상 정수 금액·대기자금·현재 보유 옵션 종류를 확인합니다. 옵트아웃은 기존 previewDefaultOptOut의 50%/전량 기준을 그대로 사용합니다. 옵트아웃과 옵션 구성품에 일반 거래의 10만원 제한을 새로 적용하지 않습니다.

비활성 안내의 표시 원칙

  • 버튼은 실제 disabled 속성을 적용하고 「이용 불가」로 표시합니다. 카드 전체를 낮은 투명도로 만들어 사유까지 흐리게 하지 않습니다.
  • 사유는 카드 설명 아래 항상 보이는 텍스트로 둡니다. 색상이나 hover 툴팁, 비활성 버튼 클릭에 의존하지 않습니다.
  • 버튼과 사유는 aria-describedby로 연결하고, 사유 문장은 읽기 순서에도 포함합니다.
  • 공통 잠금 사유가 있으면 그것을 우선 표시합니다. 그렇지 않으면 자금·보유·상품 제한을 구체적으로 설명합니다.
  • 자금·주문 요약은 첫 행동 후 한 번 갱신합니다. 상태 확인만으로 행동·거래·점수·퀴즈를 발생시키지 않습니다.
  • 두 번째 행동의 모든 유효한 선택을 자동으로 숨기거나 「이번엔 그대로」를 자동 실행하지 않습니다.

구현 시 중요한 경계

  1. 순수 판정: performAction을 시험 실행해 가능 여부를 구하지 않습니다. 메뉴 렌더 중 턴 마감·장부 기록·퀴즈·업적 흐름이 실행되지 않도록 별도 읽기 전용 검사만 사용합니다.
  2. 동일 조건: 일반 매수의 성향·한도는 기존 canBuyForProfile, decideBuyAgainstRiskLimit를 재사용합니다. confirm 결과는 거절이 아니라 가능한 금액 확인 단계입니다.
  3. 출처 구분: 일반 매도·교체는 scopedHolding(state, productId), 옵션은 해당 scope의 잔고만 확인합니다. 평가액 전체와 지금 주문 가능한 잔고를 구분합니다.
  4. 리밸런싱 단계: rebalancePlan이 남아 있는 매도 정산 단계는 일반 거래도 잠깁니다. 계획이 해제되고 매수 주문만 남으면 현재 엔진이 허용하는 다른 매매까지 일괄 잠그지 않습니다. 리밸런싱 재실행은 미결제 주문이 모두 없어야 합니다.
  5. 메뉴와 초안 분리: 이전에 선택한 상품이나 입력 금액이 부적합해도 다른 선택이 가능하면 메뉴는 열립니다. 하위 화면은 실제 불가능한 값과 사유를 보여 주거나 새 초안에 유효한 초기값을 제시합니다. 사용자 초안을 몰래 거래 가능 금액으로 바꾸지 않습니다.
  6. 재평가 시점: 첫 행동 직후, 결제 후 턴 진입, 포트폴리오에서 복귀, 저장 복원, 성향·입력 변경 시 최신 상태로 판정합니다. 가능 여부는 저장하지 않고 다시 계산합니다.
  7. 방어 계층: disabled 표시 외에 이벤트 처리기에서도 진입·확정을 확인합니다. 최종 거래 함수의 검증과 중복 명령 ID 검사는 그대로 둡니다.
  8. 의존 방향: 메뉴 판정 모듈은 엔진을 읽습니다. 실행 엔진이 메뉴 판정 모듈을 역으로 가져오지 않도록 공통 제약을 하위 모듈로 두어 순환 의존을 늘리지 않습니다.
