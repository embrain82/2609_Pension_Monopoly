## 관리 방식

- 사용자가 「개선사항에 추가해줘」라고 요청하면 이 문서에 고유 번호로 추가합니다. 같은 문제의 추가 설명은 기존 항목에 보완합니다.
- 등록 시 발생 화면·문제·개선 목표·사용자 자료를 기록하고 상태를 「접수 · 구현 플랜 대기」로 둡니다. 등록만 요청한 항목은 구현하지 않습니다.
- 사용자가 별도로 요청하면 누적 항목을 함께 검토해 우선순위, 영향 범위, 의존관계, 구현 순서와 완료 조건을 포함한 구현 플랜을 작성합니다. 실제 구현은 구현 요청을 받은 뒤 진행합니다.
- 항목의 번호를 유지하며 접수 → 계획 작성 → 구현 → 검증 완료 순서로 상태를 갱신합니다. 아직 구현하지 않은 항목을 완료로 표시하지 않습니다.
- 기존 [디폴트옵션 후속 검토](default-option-redesign.md)의 P1 항목은 별도 목록으로 유지하고, 관련 계획을 작성할 때 함께 확인합니다.

## FB-001 · 디폴트옵션 추천과 현재 선택 구분

- **발생 화면:** 게임을 처음 시작할 때 나오는 「디폴트옵션을 정해 두세요」 상품 선택 창. 모바일 플레이 중 제보.
- **사용자 의견:** “처음 시작할 때 추천하는 디폴트상품과 선택된 디폴트상품이 구분이 안 될 것 같아서 명확하게 구분이 필요해.”
- **문제:** 「성향 추천」 배지와 카드의 테두리·배경 강조만으로는 추천 상품과 현재 선택 상태를 혼동할 수 있습니다. 첨부 화면에는 고위험 상품의 추천 배지와 다른 카드의 테두리 강조가 함께 보입니다. 이미지의 테두리만으로 실제 선택값이나 포커스 상태를 단정하지 않습니다.
- **개선 목표:** 성향에 따른 추천 표시와 사용자가 현재 선택한 상품 표시를 각각 명확하게 구분합니다. 추천 상품과 선택 상품이 같거나 다른 경우 모두, 어떤 상품으로 시작하게 되는지 즉시 알 수 있어야 합니다.
- **계획 시 확인할 사항:** 「추천」과 「현재 선택됨」 문구·표시의 구분, 색상 외 식별 수단, 선택 변경 시 표시 갱신, 최종 시작 버튼과 선택값의 일치. 구체적인 디자인과 변경 범위는 통합 구현 플랜 작성 시 결정합니다.
- **현재 코드 참고:** `src/ui/default-option-view.ts`의 `renderDefaultOptionCards`는 추천 배지와 `aria-checked`/`picked` 선택 상태를 별도로 계산합니다. 시각적으로 드러나는 선택 설명을 중심으로 검토합니다. 관련 스타일은 `src/styles/main.css`입니다.
- **자료:** [사용자 첨부 화면](evidence/2026-09-10-default-option-selection.jpg).
- **상태:** 구현·검증 완료 · v1.5.1. 우선순위 P0. 상세 내용은 통합 구현 플랜을 따릅니다.

## FB-002 · 디폴트옵션 운용 창의 버튼 디자인

- **발생 화면:** 디폴트옵션 옵트인/아웃 하위 창. 첫 번째 첨부 화면의 모바일 버튼 디자인.
- **사용자 의견:** “첫 번째 캡처 이미지는 버튼 디자인 변경 필요.”
- **문제:** 첨부 화면의 버튼 디자인 개선 요청입니다. 특히 「대기자금 절반」「대기자금 전액」 버튼의 글자 정렬과 내부 여백, 크기·배치 및 옵트인/아웃 탭과의 시각적 일관성을 검토 대상으로 기록합니다. 세부 디자인은 아직 확정하지 않습니다.
- **개선 목표:** 모바일에서 버튼의 용도와 선택 상태를 쉽게 알아보고 편하게 누를 수 있는 디자인으로 정리합니다.
- **계획 시 확인할 사항:** 캡처에 보이는 버튼군의 정렬·여백·높이·터치 영역·상태 표시. FB-001의 추천/선택 구분과 FB-003의 비활성 표시가 서로 혼동되지 않도록 함께 검토합니다.
- **자료:** [사용자 첫 번째 첨부 화면](evidence/2026-09-10-default-trade-buttons.jpg).
- **상태:** 구현·검증 완료 · v1.5.1. 우선순위 P1. 상세 내용은 통합 구현 플랜을 따릅니다.

## FB-003 · 운용지시 실행 가능 여부와 비활성 사유

- **발생 화면:** 한 턴에 운용지시를 두 번 할 수 있을 때 첫 번째 행동을 마친 뒤 다시 표시되는 「무엇을 할까요?」 메뉴. 두 번째 첨부 화면에는 첫 옵트인 지시 내역과 각 운용지시의 「선택」 버튼이 함께 표시됩니다.
- **사용자 의견:** 첫 행동에서 대기자금을 전부 매수하거나 옵트인·리밸런싱을 실행해 두 번째로 가능한 운용지시가 제한될 때, 선택할 수 없는 버튼을 비활성화하면서 사유를 알려 주는 방안을 고려해 달라는 요청입니다.
- **문제:** 현재 상태에서 실행할 수 없는 메뉴도 선택 가능한 버튼처럼 보이면, 메뉴에 들어간 뒤에야 제한을 알게 됩니다. 첫 행동으로 바뀐 자금·보유분·미결제 주문 상태가 다음 선택 화면에서 드러나야 합니다.
- **개선 목표:** 실제로 실행할 수 없는 운용지시는 버튼을 비활성화하고, 해당 메뉴 가까이에 이해하기 쉬운 사유를 표시합니다. 가능한 운용지시는 계속 선택할 수 있게 합니다.
- **계획 시 확인할 사항:** 대기자금 전액 사용 또는 최소 주문금액 미달, 매도할 보유분 부족, 옵션 주문 결제 대기, 리밸런싱 진행 중 등 제한 조건을 엔진의 실행 가능 기준과 일치시킵니다. 첫 행동 직후 바뀐 상태를 반영하고, 나중에 조건이 충족되면 다시 활성화합니다.
- **안내 방식 검토:** 「주문 가능 대기자금이 부족합니다」「디폴트옵션 주문 결제 후 이용할 수 있습니다」처럼 구체적인 사유를 버튼 옆이나 아래에 표시합니다. 비활성 버튼을 눌러야만 이유를 알 수 있는 방식이나 마우스 올리기에만 의존하는 방식은 피합니다.
- **묶음 메뉴 판정:** 「디폴트옵션 옵트인/아웃」처럼 여러 기능이 있는 메뉴는 가능한 기능이 남아 있는지 함께 확인합니다. 예를 들어 대기자금이 없어도 환매 가능한 옵션 보유분이 있다면 메뉴 전체를 무조건 비활성화하지 않도록 계획에서 검토합니다.
- **자료:** [사용자 두 번째 첨부 화면](evidence/2026-09-10-action-availability.jpg).
- **상태:** 구현·검증 완료 · v1.5.1. 우선순위 P0. 상세 내용은 통합 구현 플랜을 따릅니다.

## FB-004 · 포트폴리오 확인 버튼을 운용지시 창 맨 아래로 이동

- **발생 화면:** 첫 번째 첨부 이미지의 운용지시 창. 시장 안내와 1턴 실습 설명 아래에 「포트폴리오 확인」 버튼이 보입니다.
- **사용자 요청:** 「포트폴리오 확인」 버튼을 맨 아래쪽으로 옮기기.

## FB-006 · 1회 추가납입 금액 제한과 목표 도달 속도 조정

- **발생 화면:** 두 번째 첨부 이미지의 1턴 정산. 추가납입 13,400,000원으로 행동 후 IRP가 122,934,447원이 되고, 예상 월 연금 512,227원이 목표 500,000원에 도달한 사례입니다. 화면상 시장 효과는 +1,534,447원, 내 행동 효과는 +13,400,000원으로 구분되어 있습니다.
- **사용자 요청:** 한 번에 추가납입할 수 있는 금액을 제한해, 많은 돈을 한 번에 넣어 목표 연금액에 도달하는 상황을 지연시키기.
- **문제:** 초반의 큰 추가납입 한 번으로 목표를 달성하면 이후 시장 변화와 상품 운용을 통해 목표에 접근하는 플레이 과정이 짧아질 수 있습니다.
- **개선 목표:** 1회 추가납입 규모를 제한하는 방향으로 목표 도달 속도를 조정해 여러 턴에 걸쳐 납입과 운용 판단을 경험하도록 합니다.
- **권장 규칙:** 새 게임부터 1회 최대 200만원, 같은 턴의 개인 추가납입 합계도 200만원으로 제한합니다. 두 번의 운용지시와 보너스 사건의 개인 납입이 한도를 공유하며 미사용액은 이월하지 않습니다. 퇴직급여 이전은 개인 납입 한도에서 제외합니다. 진행 중인 저장은 기존 규칙을 유지합니다. 200만원으로 구현했으며 후속 플레이테스트로 밸런스를 점검합니다.
- **영향 범위:** 엔진의 공통 납입 계산, 메뉴·빠른 금액·미리보기·실행 버튼, 보너스 선택지, 저장·챕터 복원, 규칙 식별이 가능한 결과 공유, 사용자·운영자 설명. 기존 제도 모형의 누적 납입·공제 한도와 별도의 게임 진행용 제한으로 표시합니다.
- **분석 근거:** 50시드 × 4시나리오 × 5성향 × 5후보의 5,000판 탐색 실험. 최대 납입 우선 전략에서 현행→200만원의 최초 도달 중앙값은 1→6턴(한 번이라도 도달한 판 기준), 최종 달성률은 모두 88.6%였습니다. 상품 매매·보너스 납입·퇴직급여 이전을 선택하지 않은 제한된 실험이며 실제 승률·구현 검증을 의미하지 않습니다. [원본 집계](analysis/2026-09-12-contribution-pacing.json).

## FB-007 · 게임 시작 전 투자자성향 확인과 디폴트옵션 선택

- **사용자 요청:** 게임 시작 후 성향을 고정한다면, 시작 전에 투자자성향을 먼저 알려주고 그에 맞는 디폴트옵션을 선택한 뒤 게임을 시작하도록 개선. P1에 편입.
- **발생 화면·원인:** 게임 시작 후 설정의 「성향 다시 진단」 비활성화. D스텝(`4f6952a`, 2026-09-10)에서 성향을 시작 조건으로 고정했지만 사전 확인 흐름이 부족하고 설정·성향 점검 칸에는 즉시 재진단을 권하는 이전 안내가 남아 있습니다.
- **개선 목표:** 성향 확인·필요 시 진단 → 결과와 의미 확인 → 성향에 맞는 옵션 선택 → 시작 조건 확인·게임 시작. 기존 성향을 먼저 보여주되 유지·재진단이 가능해야 하며, 기본값을 실제 진단 결과처럼 표현하지 않습니다.
- **포함 범위:** 시작 전 성향·매수 가능 범위·시작 구성 안내, 성향 변경 후 옵션 적합 여부 재검토, 추천/현재 선택 구분 유지, 게임 시작 후 고정 사유 안내, 모순된 설정·칸 설명 정정, 이어하기·재도전·주간 고정 조건 처리.
- **유지할 사항:** 캐릭터 외형과 성향 분리, 지정과 매수 구분, 직접 옵트인/아웃 규칙, 기존 진행의 성향·자산·주문 보존. 준비 중 취소로 게임을 시작하거나 기존 저장을 덮어쓰지 않습니다.
- **연계:** F06(용어·설명), F08(첫 판 안내), F10(재도전), D06·D07(선택 표시·화면 구성). F08과 합쳐 구현하더라도 FB-007 하나로 추적합니다.
- **상태:** 구현·검증 완료 · v1.7.0. 후속 P1 전체 구현 요청으로 반영했습니다. [구현·검증 기록](../implementation/2026-09-12-review-p1.md).

## FB-008 · 주사위 실행 시 게임판으로 화면 이동

- **발생 상황:** 스마트폰에서 게임판이 화면 밖으로 벗어난 위치까지 스크롤한 뒤 주사위를 굴리는 경우. 사용자 플레이 중 제보이며 이번 등록에서 별도 재현 검증은 하지 않았습니다.
- **사용자 요청:** “주사위를 굴리면 포커스가 게임판을 벗어나 있더라도 게임판으로 포커스가 이동되어 말이 이동하는 걸 확인할 수 있도록 개선.”
- **문제:** 주사위 실행 위치와 게임판의 표시 위치가 분리되어 있으면 말의 이동 과정과 도착 칸을 놓칠 수 있습니다.
- **개선 목표:** 주사위를 실행하면 게임판이 보이는 위치로 화면을 이동해 출발·이동·도착을 자연스럽게 확인할 수 있게 합니다. 여기서 포커스는 화면 스크롤과 시선 이동을 포함하는 요구로 기록하며, DOM 포커스만 옮기는 것으로 완료 처리하지 않습니다.
- **계획 시 확인할 사항:** 화면 이동과 말 애니메이션의 순서, 모바일 주소창·고정 버튼에 가려지는 영역, 이미 게임판이 보이는 경우의 불필요한 스크롤, 동작 줄이기 설정과 키보드·스크린리더 포커스. 주사위 중복 실행 방지와 기존 턴 진행·저장 복원 규칙은 유지합니다. 구체적인 동작과 구현 방식은 아래 2026-09-14 계획에 정리했습니다.
- **연계:** 기존 D03(말 이동·도착 효과), D04(모바일 게임판 배치)의 후속 사용성 개선입니다. 기존 완료 상태와 구분해 FB-008로 추적합니다.
- **자료:** 2026-09-14 사용자 텍스트 제보. 첨부 3장은 정산 화면으로, 이 항목의 이동 현상을 직접 보여주는 자료는 아닙니다.
- **계획 요약:** 입력 잠금 → 게임판 노출 여부 측정 → 필요한 경우만 화면 이동 → 주사위·말 이동 → 기존 턴 처리 순서로 연결합니다. 주소창·하단 바를 고려하고, 연타·중단·동작 줄이기·포커스 복원을 검증합니다.
- **상태:** 구현·검증 완료 · v1.9.0. 이번 네 항목 중 P1·3순위. [상세 계획](playtest-improvements-plan-2026-09-14.html#board). [검증 기록](../implementation/2026-09-14-playtest-followup.md).

## FB-009 · 정산·시장 금리·수익률 영향을 함께 확인

- **발생 화면:** 모바일 정산 창. 정산 요약, 실제 보유분 영향, 상품별 시장 예시 수익률이 긴 스크롤과 「자세히」 펼침 영역에 나뉘어 있습니다.
- **사용자 요청:** “정산 요약, 시장 금리 변화, 금리 변화로 인한 수익률 변화를 한 번에 확인할 수 있도록 합치거나 모여 있으면 좋겠어.”
- **문제:** 이번 턴의 시장 변화와 상품·내 보유분 영향, 최종 정산 결과를 연결해서 보려면 서로 떨어진 영역을 오가며 비교해야 합니다.
- **개선 목표:** 정산 요약·시장 금리의 전후 변화·상품 수익률과 실제 보유분 손익을 하나의 요약 영역으로 합치거나 서로 가까이 배치해 함께 이해할 수 있게 합니다. 2026-09-14 계획에서는 하나의 핵심 요약 영역에 모으고 보조 정보를 상세로 옮기는 구성을 권장합니다.
- **계획 시 확인할 사항:** 모바일에서 요약 정보를 비교하는 데 필요한 스크롤·펼침 횟수, 핵심 수치와 보조 설명의 밀도, 금리 변화의 %p와 수익률 %·손익 금액의 구분, 전체 상품 예시와 실제 보유분 영향의 표시 기준. 금리 외 주가·가격 변동·보수 등이 반영된 수익률 전체를 「금리만으로 발생한 수익」으로 단정하지 않으며, 현재 데이터로 설명 가능한 범위를 확인합니다. 납입·출금과 투자 성과의 구분도 유지합니다.
- **연계:** 기존 F03(자금 흐름·성과 구분), F04(시장과 실제 보유 영향), D08(시장·정산 차트)의 후속 정보 배치 개선입니다. 새로운 계산 규칙이나 상세 구현 플랜을 이번 등록에서 확정하지 않습니다.
- **자료:** [사진 1 · 정산 요약](evidence/2026-09-14-settlement-summary.jpg), [사진 2 · 실제 보유분 영향과 비교](evidence/2026-09-14-holdings-impact.jpg), [사진 3 · 상세 상품별 수익률](evidence/2026-09-14-product-returns.jpg). 첨부 이미지에는 실제 금리 전후 수치가 나타나지 않아, 금리 표시와의 연결은 사용자 요청으로 기록합니다.
- **계획 요약:** 금리 전후·%p, 정산 잔액과 시장/입출금/매매 구성, 실제 보유분 주요 2개를 하나의 핵심 요약 영역에 모읍니다. 전체 상품 예시와 비교는 상세로 옮기고 퀴즈를 다음 버튼 가까이 배치합니다. 금리만의 기여 손익을 새로 추정하지 않습니다.
- **상태:** 구현·검증 완료 · v1.9.0. 이번 네 항목 중 P1·4순위. [상세 계획](playtest-improvements-plan-2026-09-14.html#summary). [검증 기록](../implementation/2026-09-14-playtest-followup.md).

## FB-010 · 퀴즈를 풀지 않고 넘어갈 때 확인 안내

- **발생 상황:** 풀 수 있는 퀴즈가 남아 있는데 사용자가 풀지 않고 다음 단계로 넘어가려는 경우. 사용자 제보로 등록하며 구체적인 발생 화면과 전환 경로는 구현 플랜 작성 시 확인합니다.
- **사용자 요청:** “퀴즈가 있을 경우 풀지 않고 다음으로 넘어가고자 할 때 점수를 획득할 수 있는 퀴즈를 풀지 않고 넘기겠냐는 안내 팝업 추가.”
- **개선 목표:** 미응답 퀴즈를 건너뛰기 전에 점수를 얻을 기회가 남아 있음을 알리고, 퀴즈를 풀거나 그대로 넘어갈 수 있도록 확인 팝업을 제공합니다. 퀴즈 응답을 강제하지 않습니다.
- **안내 방향:** 예시 문구는 「퀴즈로 점수를 얻을 수 있습니다. 풀지 않고 넘어가시겠어요?」이며 「퀴즈 풀기」「그냥 넘어가기」처럼 선택 결과를 명확히 구분합니다. 권장 문구와 표시 조건은 아래 2026-09-14 계획을 따릅니다.
- **계획 시 확인할 사항:** 실제 응답 가능 여부와 점수 획득 조건에 맞춰 안내하고, 이미 푼 퀴즈나 퀴즈가 없는 경우에는 표시하지 않습니다. 단순 응답만으로 점수가 보장되거나 건너뛰면 기존 점수가 차감되는 것처럼 표현하지 않습니다. 확인 취소·퀴즈 복귀·건너뛰기에서 턴이 중복 진행되거나 점수가 중복 반영되지 않아야 합니다.
- **자료:** 2026-09-14 사용자 텍스트 제보.
- **계획 요약:** 실제 미응답·응답 가능·추가 점수 가능 여부를 판정해 정산 종료, 퀴즈 건너뛰기/X, 다음 주사위 및 마지막 결과 진입에 공통 확인을 적용합니다. 「퀴즈 풀기/그냥 넘어가기」를 제공하며 같은 턴·같은 기회의 확인은 반복하지 않습니다. 정산 X는 보드 확인으로 유지하고 점수 기회가 있을 때 자동 넘기기를 중지합니다.
- **상태:** 구현·검증 완료 · v1.9.0. 이번 네 항목 중 P0·2순위. [상세 계획](playtest-improvements-plan-2026-09-14.html#quiz). [검증 기록](../implementation/2026-09-14-playtest-followup.md).

## FB-011 · 시장 변화에 따른 위험자산 비중 초과 안내

- **발생 상황:** 주사위를 굴린 뒤 시장 금리·가격 변화가 보유자산에 반영되어 위험자산 비중이 70%를 초과한 상태에서 「이번 턴 운용하기」를 누르는 경우.
- **사용자 요청:** “주사위 굴린 후 시장금리변화로 위험자산한도가 70% 초과했을 때 이번 턴 운용하기 버튼을 누를 때 위험자산한도가 초과했다는 안내 팝업 추가.”
- **첨부 화면:** 위험자산 비중 70.6%와 「시장 상승으로 한도 초과 · 위험자산 추가매수 제한, 예금·채권 매수나 리밸런싱은 가능」이라는 기존 안내, 하단의 「이번 턴 운용하기」 버튼이 보입니다. 금리만으로 초과가 발생했는지는 이미지로 단정하지 않습니다.
- **문제:** 보드의 비중 표시와 안내를 놓치면, 운용 메뉴에 들어갈 때 현재 한도 초과 상태와 거래 제한을 인지하지 못할 수 있습니다.
- **개선 목표:** 시장 반영 후 위험자산 비중이 70%를 초과한 상태에서 운용하기를 누르면 안내 팝업으로 현재 비중·한도 초과 상태를 먼저 알리고 운용 메뉴로 연결합니다. 표현은 「한도가 증가」한 것으로 오해되지 않도록 「위험자산 비중이 70% 한도를 초과」로 구분합니다.
- **계획 시 확인할 사항:** 표시용 반올림 수치와 실제 엔진 판정의 일치, 시장 반영에 따른 초과와 신규 매수 제한의 구분, 동일 턴 재진입 시 반복 안내 범위, 정상 비중으로 돌아온 뒤 표시 해제. 가능한 거래 안내는 당시 자금·보유분·주문 상태와 공통 실행 가능 판정을 따릅니다. 안내만으로 강제 매도하거나 모든 운용지시를 막는 규칙은 추가하지 않으며, 권장 문구·닫기·확인 동작은 아래 2026-09-14 계획에 정리했습니다.
- **연계:** FB-003(운용지시 실행 가능 여부), FB-009(시장 변화와 자산 영향 연결), 기존 F04(실제 시장 영향 설명). 이번 요청은 안내 시점 개선으로 관리하며 제도·거래 규칙 변경은 확정하지 않습니다.
- **자료:** [사용자 첨부 · 위험자산 비중 70.6%와 운용하기 버튼](evidence/2026-09-14-risk-limit-notice.jpg).
- **계획 요약:** 수동·자동 운용 진입 전에 시장 당시 초과와 현재 비중을 재평가합니다. 같은 턴 확인 후에는 반복하지 않으며 X는 보드 복귀로 처리합니다. 납입 등으로 정상화되면 안내와 기존 대시보드 표시를 해제하고, 거래 가능 여부는 기존 공통 판정을 유지합니다.
- **상태:** 구현·검증 완료 · v1.9.0. 이번 네 항목 중 P0·1순위. [상세 계획](playtest-improvements-plan-2026-09-14.html#risk). [검증 기록](../implementation/2026-09-14-playtest-followup.md).

## FB-012 · 미진단 첫 진입에서 성향을 숨기고 진단 안내

- **제보:** 처음 진입하여 투자자성향이 없으면 성향을 보여주지 않고 진단으로 유도.
- **확인:** 시작 준비가 기본값인 위험중립형·설명·눈금·시작 배분을 표시합니다. 진단 이력이 없는 설정 저장을 다시 읽으면 legacy로 처리되어 확인 단계로 넘어갈 수 있는 경로도 확인했습니다.
- **제안:** 이력 없는 신규 사용자는 미진단 안내와 진단 버튼을 먼저 표시합니다. 진단 완료 후 결과 → 디폴트옵션 → 최종 시작으로 진행합니다. 저장된 유효 이력·구 판 이어하기·주간 공통 성향은 구분합니다.
- **자료:** [사용자 화면](evidence/2026-09-15-unassessed-profile.jpg).
- **상태:** 구현 반영 · 자동 검사 통과 / 직접 플레이·시각 검증 중. [상세 계획](playtest-improvements-plan-2026-09-15.html#profile).

## FB-014 · 첫 시장 반영 후 위험 한도 초과를 줄이는 시작 배분

- **제보:** 첫 주사위 후 위험비중이 70%를 넘는 경우가 많아 초기 포트폴리오 조절 요청.
- **확인:** 공격투자형의 시작 위험비중이 정확히 70%입니다. 네 시장 각각 1,000개 동일 시드의 첫 시장 비교에서 현재 초과율 30.7~69.2%, 65% 시작 후보는 표본 내 초과 0건입니다. 이는 도착·운용·후속 턴을 포함한 전체 플레이 검증이 아닙니다.
- **제안:** 신규 공격투자형만 예금 35%·혼합형 20%·ETF 45%로 출발. 다른 성향·기존 리밸런싱 목표·70% 한도 판정은 유지. 구 판은 원래 규칙으로 이어하고 고스트·분기·비교 기준을 같은 규칙으로 계산합니다.
- **자료:** [계획용 비교 결과](analysis/2026-09-15-opening-risk.json) · [재현 스크립트](analysis/2026-09-15-opening-risk.mjs).
- **상태:** 구현 반영 · 자동 검사 통과 / 직접 플레이·시각 검증 중. [상세 계획](playtest-improvements-plan-2026-09-15.html#allocation).

## FB-015 · IRP 대기자금 이자 확인과 처리 정책

- **제보:** IRP 대기자금에 이자가 부여되는지 점검 요청.
- **확인:** 현재 시장 엔진은 보유 예금 이자는 계산하지만 IRP 대기자금에는 이자를 붙이지 않습니다.
- **제안:** 신규 판의 턴 시작 주문 가능 대기자금에 턴당 0.1% 교육용 이자를 자동 반영하는 안을 권장합니다. 현재 0%를 유지하고 생략 가정을 설명하는 대안도 제시했습니다. 2026-09-15 사용자 승인으로 0.1% 권장안을 구현했습니다.
- **영향:** 정산·운용지수·수령 계산·저장 버전·고스트·분기 재현. 납입·세액공제와 구분하고 예약/미결제·중복 지급·최종 주문 마무리에서 검증합니다. 특정 금융회사의 실제 연이율을 뜻하지 않습니다.
- **상태:** 0.1% 권장안 승인·구현 반영 · 금융 규칙 검사 통과 / 통합 검증 중. [상세 계획·계산 예시](playtest-improvements-plan-2026-09-15.html#interest).

## FB-018 · 예금 만기 후 디폴트옵션 자동운용

- **제보:** 같은 날 세 번째 첨부 화면. 현재는 만기 후 이자를 중단하고 예금 보유분을 남깁니다. 일정 기간 후 지정 옵션 매수가 반영되도록 조사·계획 요청.
- **공식 자료 확인:** 기존 상품 만기 후 4주간 무지시 → 통지 → 통지 후 2주간 무지시 → 적용. 신규 가입의 미지시 자금은 별도 절차이며, 옵션 안의 예금은 구성·상품 약정에 따라 재예치 예외가 있습니다.
- **권장 게임 표현:** 만기 T → 통지 T+1 → 자동주문 T+2. 실제 주 수와 게임 단계의 차이를 명시하며, 현실의 경과 시간은 사용하지 않습니다.
- **금융 처리:** 일반 운용 예금·예금 100% 옵션은 만기해지형, 혼합 옵션 내부 예금은 재예치형인 가상 계약으로 제안합니다. 만기 자금은 IRP 현금의 하위 잔액으로 추적해 중복 계산을 막습니다. 직접 사용액은 대상액에서 차감하고 일반 대기자금은 끌어오지 않습니다.
- **화면:** 기존 운용 메뉴 유지. 만기 안내 카드와 상세 타임라인을 추가하고, 현금 유지 지시는 만기자금 상세에서만 선택하도록 제안합니다.
- **호환·검증:** 새 금융 규칙은 새 판부터 적용. 미지정·지정 변경·다른 옵션 보유·대기 주문·복수 만기·소액·12턴 종료·새로고침·복기·중복 이자/주문을 검증합니다.
- **범위:** [디폴트옵션 후속 검토](default-option-redesign.md)의 자동운용 과제를 구체화합니다. 신규 입금 자동운용·다중 옵션 보유는 별도 확장으로 유지합니다.
- **상태:** 구현·검증 완료 · v1.13.0. 만기 대상액 장부·통지 실제 표시 기록·자동주문·현금 유지 지시·구판 호환 적용. [공식 출처와 상세 구현계획](playtest-improvements-plan-2026-09-16.html#default).
