# 플레이테스트 개선사항

사용자가 플레이 중 전달하는 개선사항을 누적하는 목록입니다. 최초 등록: 2026-09-10 · 기준 버전: v1.5.0.

FB-001~003의 [상세 구현 플랜과 화면 시안](playtest-improvements-plan-2026-09-10.html)을 작성했습니다. v1.5.1에서 세 항목의 구현·검증을 완료했습니다. [구현·검증 기록](../implementation/2026-09-10-playtest-feedback.md)을 참고하세요.

## 관리 방식

- 사용자가 「개선사항에 추가해줘」라고 요청하면 이 문서에 고유 번호로 추가합니다. 같은 문제의 추가 설명은 기존 항목에 보완합니다.
- 등록 시 발생 화면·문제·개선 목표·사용자 자료를 기록하고 상태를 「접수 · 구현 플랜 대기」로 둡니다. 등록만 요청한 항목은 구현하지 않습니다.
- 사용자가 별도로 요청하면 누적 항목을 함께 검토해 우선순위, 영향 범위, 의존관계, 구현 순서와 완료 조건을 포함한 구현 플랜을 작성합니다. 실제 구현은 구현 요청을 받은 뒤 진행합니다.
- 항목의 번호를 유지하며 접수 → 계획 작성 → 구현 → 검증 완료 순서로 상태를 갱신합니다. 아직 구현하지 않은 항목을 완료로 표시하지 않습니다.
- 기존 [디폴트옵션 후속 검토](default-option-redesign.md)의 P1 항목은 별도 목록으로 유지하고, 관련 계획을 작성할 때 함께 확인합니다.

## FB-001 · 디폴트옵션 추천과 현재 선택 구분

- **발생 화면:** 게임을 처음 시작할 때 나오는 「디폴트옵션을 정해 두세요」 상품 선택 창. 모바일 플레이 중 제보.
- **사용자 의견:** “처음 시작할 때 추천하는 디폴트상품과 선택된 디폴트상품이 구분이 안 될 것 같아서 명확하게 구분이 필요해.”
- **문제:** 「성향 추천」 배지와 카드의 테두리·배경 강조만으로는 추천 상품과 현재 선택 상태를 혼동할 수 있습니다. 첨부 화면에는 고위험 상품의 추천 배지와 다른 카드의 테두리 강조가 함께 보입니다. 이미지의 테두리만으로 실제 선택값이나 포커스 상태를 단정하지 않습니다.
- **개선 목표:** 성향에 따른 추천 표시와 사용자가 현재 선택한 상품 표시를 각각 명확하게 구분합니다. 추천 상품과 선택 상품이 같거나 다른 경우 모두, 어떤 상품으로 시작하게 되는지 즉시 알 수 있어야 합니다.
- **계획 시 확인할 사항:** 「추천」과 「현재 선택됨」 문구·표시의 구분, 색상 외 식별 수단, 선택 변경 시 표시 갱신, 최종 시작 버튼과 선택값의 일치. 구체적인 디자인과 변경 범위는 통합 구현 플랜 작성 시 결정합니다.
- **현재 코드 참고:** `src/ui/default-option-view.ts`의 `renderDefaultOptionCards`는 추천 배지와 `aria-checked`/`picked` 선택 상태를 별도로 계산합니다. 시각적으로 드러나는 선택 설명을 중심으로 검토합니다. 관련 스타일은 `src/styles/main.css`입니다.
- **자료:** [사용자 첨부 화면](evidence/2026-09-10-default-option-selection.jpg).
- **상태:** 구현·검증 완료 · v1.5.1. 우선순위 P0. 상세 내용은 통합 구현 플랜을 따릅니다.

## FB-002 · 디폴트옵션 운용 창의 버튼 디자인

- **발생 화면:** 디폴트옵션 옵트인/아웃 하위 창. 첫 번째 첨부 화면의 모바일 버튼 디자인.
- **사용자 의견:** “첫 번째 캡처 이미지는 버튼 디자인 변경 필요.”
- **문제:** 첨부 화면의 버튼 디자인 개선 요청입니다. 특히 「대기자금 절반」「대기자금 전액」 버튼의 글자 정렬과 내부 여백, 크기·배치 및 옵트인/아웃 탭과의 시각적 일관성을 검토 대상으로 기록합니다. 세부 디자인은 아직 확정하지 않습니다.
- **개선 목표:** 모바일에서 버튼의 용도와 선택 상태를 쉽게 알아보고 편하게 누를 수 있는 디자인으로 정리합니다.
- **계획 시 확인할 사항:** 캡처에 보이는 버튼군의 정렬·여백·높이·터치 영역·상태 표시. FB-001의 추천/선택 구분과 FB-003의 비활성 표시가 서로 혼동되지 않도록 함께 검토합니다.
- **자료:** [사용자 첫 번째 첨부 화면](evidence/2026-09-10-default-trade-buttons.jpg).
- **상태:** 구현·검증 완료 · v1.5.1. 우선순위 P1. 상세 내용은 통합 구현 플랜을 따릅니다.

## FB-003 · 운용지시 실행 가능 여부와 비활성 사유

- **발생 화면:** 한 턴에 운용지시를 두 번 할 수 있을 때 첫 번째 행동을 마친 뒤 다시 표시되는 「무엇을 할까요?」 메뉴. 두 번째 첨부 화면에는 첫 옵트인 지시 내역과 각 운용지시의 「선택」 버튼이 함께 표시됩니다.
- **사용자 의견:** 첫 행동에서 대기자금을 전부 매수하거나 옵트인·리밸런싱을 실행해 두 번째로 가능한 운용지시가 제한될 때, 선택할 수 없는 버튼을 비활성화하면서 사유를 알려 주는 방안을 고려해 달라는 요청입니다.
- **문제:** 현재 상태에서 실행할 수 없는 메뉴도 선택 가능한 버튼처럼 보이면, 메뉴에 들어간 뒤에야 제한을 알게 됩니다. 첫 행동으로 바뀐 자금·보유분·미결제 주문 상태가 다음 선택 화면에서 드러나야 합니다.
- **개선 목표:** 실제로 실행할 수 없는 운용지시는 버튼을 비활성화하고, 해당 메뉴 가까이에 이해하기 쉬운 사유를 표시합니다. 가능한 운용지시는 계속 선택할 수 있게 합니다.
- **계획 시 확인할 사항:** 대기자금 전액 사용 또는 최소 주문금액 미달, 매도할 보유분 부족, 옵션 주문 결제 대기, 리밸런싱 진행 중 등 제한 조건을 엔진의 실행 가능 기준과 일치시킵니다. 첫 행동 직후 바뀐 상태를 반영하고, 나중에 조건이 충족되면 다시 활성화합니다.
- **안내 방식 검토:** 「주문 가능 대기자금이 부족합니다」「디폴트옵션 주문 결제 후 이용할 수 있습니다」처럼 구체적인 사유를 버튼 옆이나 아래에 표시합니다. 비활성 버튼을 눌러야만 이유를 알 수 있는 방식이나 마우스 올리기에만 의존하는 방식은 피합니다.
- **묶음 메뉴 판정:** 「디폴트옵션 옵트인/아웃」처럼 여러 기능이 있는 메뉴는 가능한 기능이 남아 있는지 함께 확인합니다. 예를 들어 대기자금이 없어도 환매 가능한 옵션 보유분이 있다면 메뉴 전체를 무조건 비활성화하지 않도록 계획에서 검토합니다.
- **자료:** [사용자 두 번째 첨부 화면](evidence/2026-09-10-action-availability.jpg).
- **상태:** 구현·검증 완료 · v1.5.1. 우선순위 P0. 상세 내용은 통합 구현 플랜을 따릅니다.
