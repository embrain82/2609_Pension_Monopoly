# 04안 적용 및 캐릭터 표정 애니메이션 검토

2026-09-16. 사용자 승인 범위: 칸 이름 배치 04안 적용. 이후 표정 애니메이션은 가능성 검토이며 게임 적용은 별도 결정한다.

## 이번 적용

- `src/ui/board.ts`: 공개된 칸의 아이콘을 x=11, y=76, 12×12로 이동. 이름을 x=57, 기준선 y=86으로 이동.
- `src/styles/design-d2a.css`: 모바일/데스크톱 모두 14, 굵기 650, 자간 −0.3. 한 칸 100×100인 SVG 좌표 기준.
- `src/styles/board-discovery.css`: 현재 칸의 아이콘 숨김 제거.
- 기존 판과 새 판 모두 표시만 바뀐다. 미공개 칸은 기존 지도 스티커를 유지한다. 주사위·이동·금융 계산·저장 형식은 수정하지 않는다.

## 검토 근거

- `src/ui/avatars.ts`: 캐릭터별 2172×724 PNG의 세 포즈를 잘라 평온/긴장/기쁨을 표시한다. 각 프레임 중심과 발 위치 보정값이 이미 있다.
- `src/ui/token3d.ts`: 바깥 `.token-pos`는 좌표 이동, `.token3d`는 점프/착지 Web Animations API 변환을 담당한다.
- `src/styles/characters.css`: `.token-face`는 기존 발 정렬을 위해 translateY(−17%)를 사용한다. 여기에 추가 transform을 덮어쓰면 안 된다.
- `src/ui/app.ts`: 이동 → 칸 공개 → `startTurn` → 시장/사건 창 또는 보드 렌더 순서다. 별도 연출로 엔진 처리나 저장을 지연시키지 않는다.
- 현행 `avatarMood`는 목표 충족을 기쁨으로 우선 판정한다. 그 외 시장 충격 또는 최근 IRP 기록 간 5% 이상 감소는 긴장, 나머지는 평온이다. 이번 작업에서 판정은 바꾸지 않았다.

## 권장 구현 범위 (미승인)

1. 기존 세 포즈를 유지하고 그림 내부에 독립 애니메이션 레이어를 추가한다. 평온 호흡 1.6초, 긴장 좌우 떨림 0.7초, 기쁨 작은 들썩임 1초를 턴당 한 번 재생한다.
2. 시장 반영 완료와 이동/공개 완료를 확인한 뒤, 모달이 없고 보드가 보일 때 시작한다. 모달이 열렸으면 pending으로 남겨 닫은 후 재생한다. 게임 진행 버튼은 연출 때문에 막지 않는다.
3. 감정 움직임은 이동용 AnimationController와 별도의 취소 핸들을 둔다. 모달 열림, 주사위 시작, 탭 숨김, 캐릭터 변경/숨김, 화면 이동 때 취소한다. 실제 재생 시작 후에는 같은 턴 재생을 소비한 것으로 처리한다.
4. 턴 번호/표정/재생 여부는 UI 진행 정보로만 관리한다. 엔진에는 추가하지 않는다. 새로고침에서는 재생을 소급하지 않는다. 포트폴리오 조회나 DOM 갱신만으로 재생하지 않는다.
5. 앱의 움직임 줄이기와 OS 설정을 모두 따른다. 캐릭터 표시 끔에서는 평면 말을 유지한다. 애니메이션 종료/취소 후 반드시 원래 발 위치로 돌아온다.
6. 그림이 준비되기 전에 재생하거나 이미지 실패 시 빈 말을 표시하지 않는다. 기존 이름 대체 표시와 파일 캐시를 유지한다.

추가 논의: 목표 충족+시장 충격에서 기쁨 우선 문제, 입출금이 포함될 수 있는 잔액 감소를 투자 손실처럼 읽는 문제. 더 정확한 감정 판정을 넣는다면 시장 손익 원장 기반 긴장 우선 및 목표 신규 달성 시 기쁨을 제안한다. 수치 기준은 승인 후 정한다.

눈/입의 실제 연속 변화는 기존 전체 몸 PNG 3장만으로 만들 수 없다. 추가 중간 프레임(캐릭터×감정당 4~6프레임) 또는 얼굴 레이어 분리 작업이 필요하다. 1차는 현재 포즈와 몸 움직임을 권장한다.

## 검토 페이지

- `index.html`: 5개 이미지가 base64로 포함된 독립 HTML. 각 정지 포즈와 움직임 버튼, 움직임 줄이기, 구현 계획을 포함한다. 게임 코드를 import하거나 플레이 저장소를 읽지 않는다.
- `template.html`, `build.mjs`: `node docs/design/2026-09-16-character-motion/build.mjs`로 재생성.
- 검토 움직임은 연속 표정 변형이 아니라 이미 준비된 정지 표정 + 몸 전체 이동/확대다. 게임에는 적용하지 않았다.

## 검증

- 기존 67개 파일 / 688개 테스트, 타입 검사, 린트, 프로덕션 빌드 통과.
- 브라우저 확인 결과는 `qa-layout.json` 및 `qa-review.json`에 기록한다. `qa-layout.json`은 실제 게임 렌더 함수와 CSS를 사용한 표시용 fixture이며 직접 플레이와 구분한다.
- 320/390/768/1440px에서 5캐릭터×3표정 모두 이름과 겹치지 않고 현재 칸 아이콘이 보인다. 24개 이름의 경계 검사와 페이지 가로 넘침 검사도 통과했다.
- 390×844 직접 플레이에서 성향 진단→옵션 선택→주사위→12칸 이동→13번 칸 공개를 확인했다. 새로고침·이어하기 전후 게임 상태의 깊은 비교가 일치한다.
- 검토 페이지의 15개 포즈 이미지 디코딩, 세 가지 재생, 움직임 줄이기에서 애니메이션 0개, 외부 이미지 참조 0개를 확인했다. 스크린샷에서 각 프레임이 하나씩 잘려 보이는지도 확인했다.
- 향후 애니메이션 적용 시 이동/공개/시장 반영 1회, 5캐릭터×3표정, 모달 왕복/재시작/백그라운드 전환, 움직임 줄이기, 저장 복원 및 금융 원장 불변 조건을 추가 확인해야 한다.
